# WU-0A-07 Proposal: HarnessCommand Taxonomy and Typed Invoke Helper

## Design

Add a narrow command-name contract for the three Phase 0A IPC commands documented by the WU:

- `get_harness_settings`
- `subscribe_workspace_events`
- `ping_runtime`

TypeScript owns the frontend command union, command-specific argument/response lookup, response parsers, `CommandError` taxonomy, and `invokeCommand` helper. Rust owns only the command-name taxonomy and parser in `src-tauri/src/contracts/harness_command.rs`.

The TypeScript helper exposes a command-mapped signature:

```text
invokeCommand<TResponse, TArgs>(
  command: HarnessCommand,
  args: TArgs
) -> Promise<TResponse>
```

The implementation narrows that generic surface with per-command mappings:

- `get_harness_settings`: `{}` args, `HarnessSettings` response from WU-0A-02.
- `subscribe_workspace_events`: `{ topic: EventTopic, channelId: string }` args, subscription ack response.
- `ping_runtime`: `{}` args, ping response shape.

The helper serializability-checks args before invoking Tauri and parses the response after the shim resolves. Parser failure maps to `ResponseDeserializationFailed`.

## Test Seam

Tests use a fixture-controlled invoke shim through an injected dependency. The real `@tauri-apps/api/core` `invoke` import is the production default, but unit tests construct a helper with a local shim so no running Tauri runtime or registered command handler is required.

`InvokeRejected` is exercised by a shim that rejects. `ResponseDeserializationFailed` is exercised by a shim that resolves with a deliberately invalid fixture response.

## CommandError Taxonomy

The frontend error taxonomy is:

- `UnknownCommand`: command is not one of the three documented names.
- `ArgumentSerializationFailed`: args cannot be serialized for Tauri invoke, such as circular references or `BigInt`.
- `InvokeRejected`: the invoke shim rejects before a response is available.
- `ResponseDeserializationFailed`: the invoke shim resolves, but the response does not match the command-specific parser.

Rust does not expose this runtime error taxonomy in Phase 0A because no Rust command handler is registered by this WU.

## Anti-Scope

- No real Tauri command registration at the runtime invoke handler.
- No `subscribe_workspace_events` event producer or `Channel` lifecycle.
- No `ping_runtime` Rust command implementation.
- No `get_harness_settings` command handler wiring.
- No GraphStore tables, migrations, provider credentials, agent invocation, or domain event producers.

The Tauri builder stays without `.invoke_handler()`, and `registered_command_count() == 0` remains the Phase 0A invariant.

## Supported Surface

- Deployment mode: local Phase 0A Tauri scaffold and frontend contract consumers.
- Customer cohort: internal contract consumers and future IPC slices.
- Public paths: TypeScript imports of `src/contracts/harness-command.ts` and `src/ipc/invoke-command.ts`, plus Rust imports of `agent_harness_lib::contracts::harness_command`.
- Adjacent paths in blast radius: WU-0A-02 `HarnessSettings`, WU-0A-05 `EventTopic`, contract module declarations, and `bun run *` / Cargo checks.
- Migration path: additive taxonomy, helper, fixtures, and tests.
- Rollback path: remove WU-0A-07 files and module declarations.
- Observability: Rust contract tests and Vitest tests expose command-name drift, invalid command acceptance, serialization failure mapping, invoke rejection mapping, and response parser drift.

## Assumptions

- A1: `channelId` is the frontend-owned registration handle for `subscribe_workspace_events` in this WU. Evidence: ticket asks to preserve "channel-id args" and excludes event producer implementation. Invalidated by a revised WU requiring Tauri `Channel` objects in this slice.
- A2: The ping response can be a small fixture-owned health object because the ticket only requires a documented ping response shape and excludes a Rust ping implementation. Evidence: acceptance checks only fixture-controlled invoke success. Invalidated by a revised WU specifying a backend-generated ping schema.
- A3: Arg serializability can be validated with JSON-compatible runtime checks before calling invoke. Evidence: ticket names circular references, symbols, and fixture-controlled shims, not runtime Tauri serialization internals. Invalidated by a revised WU requiring exact Tauri serializer parity.
- A4: Runtime command registration remains empty. Evidence: ticket explicitly requires no invoke handler registration and the existing `registered_command_count() == 0` invariant. Invalidated only by a revised Phase 0A command-registration WU.

## Test Intent

- Rust command taxonomy and serde round-trip: verify every command fixture deserializes and reserializes, and alternate/unknown names are rejected. Risk: Rust command-name drift. Level: particular-integration. Fixtures: `command-names.json`, `alternate-command-names.json`. Assumptions: A4.
- TypeScript command taxonomy and parser parity: verify the union, parser, and fixture names align with Rust-owned fixtures and reject alternate names. Risk: TS accepts command names Rust rejects. Level: unit/typecheck. Fixtures: `command-names.json`, `alternate-command-names.json`.
- Typed invoke happy paths: verify fixture shim calls preserve command and args for `ping_runtime`, `get_harness_settings`, and `subscribe_workspace_events`, and responses parse to documented shapes. Risk: helper erases command-specific contracts or opens real runtime paths. Level: unit. Fixtures: happy-path JSON files. Assumptions: A1, A2, A4.
- CommandError reachability: verify unknown command, non-serializable args, invoke rejection, and bad response fixtures map to documented error variants. Risk: errors are renamed, unreachable, or leak raw Tauri errors. Level: unit. Fixtures: `command-errors.json`, `invalid-ping-runtime-response.json`, direct JS circular/BigInt object for non-serializable args. Assumptions: A3.
