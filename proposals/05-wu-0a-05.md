# WU-0A-05 Proposal: EventTopic Taxonomy

## Design

Add a narrow shared event-topic taxonomy for Phase 0A:

- Rust owns the serde contract enum and error enum in `src-tauri/src/contracts/event_topic.rs`.
- Rust event subscription parsing lives in `src-tauri/src/events/topic.rs`.
- TypeScript mirrors the topic union, parse error union, and parser in `src/contracts/event-topic.ts`.
- Contract fixtures under `product-strategy/contracts/fixtures/wu-0a-05/` are the cross-language source of truth for topic names, parser success cases, parser error cases, inert placeholders, and Phase 0A live topics.

Parsing is exact-match and lowercase. The empty string returns `EmptyTopic`; any other undocumented string, including whitespace-padded or differently-cased input, returns `UnknownTopic`.

## Scope

- Preserve the documented `EventTopic` variants: `graph`, `render`, `provider`, `optimizer`, `worker`, `question`, `recovery`, `budget`, `audit`, and `runtime`.
- Preserve the documented `EventTopicError` variants: `UnknownTopic` and `EmptyTopic`.
- Expose a parser that rejects unknown strings before they can be used as subscription topics.
- Make `runtime` the only Phase 0A live emission target while keeping all other topics as inert placeholders.

## Anti-Scope

- No IPC subscription command implementation.
- No event payload schema beyond the topic taxonomy.
- No GraphStore, provider, optimizer, worker, question queue, recovery, budget, or audit producer work.
- No changes to WU-0A-01 scaffold behavior or WU-0A-02 settings behavior beyond additive module wiring.

## Supported Surface

- Deployment mode: local Phase 0A desktop scaffold.
- Customer cohort: developer/test harness consumers only.
- Public paths: Rust library consumers and TypeScript contract importers.
- Adjacent paths: existing Tauri bootstrap, React shell, and settings loader remain unchanged.
- Migration path: additive contract, event-topic module, fixtures, and tests.
- Rollback path: remove the added WU-0A-05 files and module declarations.
- Observability: fixture-backed tests verify exact taxonomy, parser behavior, inert placeholders, and live-topic gating.

## Assumptions

- A1: Phase 0A has no real event producers except runtime lifecycle-style events. Evidence: ticket acceptance criteria says only `runtime` may emit real Phase 0A payloads. Invalidated by a revised WU-0A-05 contract adding another live Phase 0A topic.
- A2: Topic parsing should not normalize input. Evidence: documented canonical strings are lowercase and the parser has explicit `EmptyTopic` and `UnknownTopic` errors only. Invalidated by a revised contract requiring trimming or case folding.
- A3: Unknown-topic rejection can be represented as a parser invariant before IPC wiring exists. Evidence: ticket asks for taxonomy and parser only, with no IPC command boundary in scope. Invalidated by a revised ticket adding a concrete subscription command.

## Test Intent

- Rust taxonomy and serde round-trip: verify every documented topic serializes to its lowercase string and the enum set exactly matches the fixture. Risk: Rust/TS contract drift. Level: particular-integration. Fixture: `event-topics.json`.
- Rust parser success/error behavior: verify documented success cases and `EmptyTopic`/`UnknownTopic` errors. Risk: unknown subscription strings reach event routing. Level: unit. Fixtures: `parse-success.json`, `parse-errors.json`.
- Rust Phase 0A live-topic gating: verify later-domain placeholders are present and inert while `runtime` is the only live topic. Risk: Phase 0A accidentally exposes later-domain event payload producers. Level: unit. Fixtures: `inert-topics.json`, `phase-0a-live-topics.json`.
- TypeScript taxonomy and parser parity: verify the TypeScript union constants match the fixture and parser behavior matches Rust-owned cases. Risk: TypeScript accepts topic strings Rust rejects. Level: unit/typecheck. Fixtures: `event-topics.json`, `parse-success.json`, `parse-errors.json`.
