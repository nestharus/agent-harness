# WU-0A-13 Proposal: Workspace Route Shell

## Design

Add two TanStack Router routes to the existing code-based router:

- `/workspace/$workspaceId`
- `/workspace/$workspaceId/node/$nodeId`

Both routes render the same `<WorkspaceShell />` component. The root route becomes an outlet wrapper so child routes render once, while the existing `/` scaffold remains available as the index route.

`WorkspaceShell` reads `workspaceId` and optional `nodeId` from route params, reads the `pane` query value, parses it with WU-0A-11 `parsePaneId`, and falls back to `runtimeStatus` when the query is absent, empty, or unknown. It builds a `ShellRegionState` with WU-0A-12 fields:

- `workspaceId` from route params.
- `selectedNodeId` from the optional node route param.
- `activePane` from the parsed query or `runtimeStatus` fallback.
- `actionNeededCount: 0` and `passiveProgressCount: 0` as Phase 0A placeholders.
- `runtimeConnected: false` as a Phase 0A runtime placeholder.

The shell does not call `invokeCommand("ping_runtime", {})`. WU-0A-07 defines the TypeScript command contract, but the current Rust Phase 0A scaffold registers only `subscribe_workspace_events`; calling `ping_runtime` from the shell would create a runtime mismatch. The runtime pane therefore displays live Phase 0A shell state only: connected is `false` and pending until a later WU registers a runtime command.

The route-state derivation lives in `src/contracts/workspace-route-shell.ts` so tests and route modules share a pure contract boundary. Fixture round trips use WU-0A-12 `parseShellRegionState`.

## Routing Invariant

Both workspace routes render exactly one `WorkspaceShell` root. There is no nested workspace shell and no parent workspace layout wrapping a child workspace layout. Route params select view-model state only; they do not load GraphStore nodes.

## Active Pane Derivation

`?pane=<value>` is parsed by `parsePaneId`. Missing, empty, non-string, and unknown values fall back to `runtimeStatus`. The fallback does not mutate workspace state and does not emit IPC.

## Selected Node

`/workspace/:workspaceId/node/:nodeId` copies `nodeId` into `ShellRegionState.selectedNodeId`. `/workspace/:workspaceId` omits `selectedNodeId`.

## Action And Passive Counters

`actionNeededCount` and `passiveProgressCount` remain static `0` placeholders in Phase 0A. They are not wired to graph, worker, optimizer, question, or evidence producers.

## Anti-Scope

- No Rust changes and no new Tauri commands.
- `phase_0a_scaffold_commands()` remains length `1`.
- No GraphStore queries, node fetches, migrations, or sqlx migration apply.
- No `/home/nes/.local/bin/agents` invocation.
- No provider config reads.
- No `invokeCommand("ping_runtime", {})` from this route shell.
- No real domain pane implementation; non-runtime panes are inert placeholders.

## Supported Surface

- Deployment mode: local Phase 0A Tauri/Vite desktop scaffold.
- Customer cohort: developer/test harness consumers.
- User-reachable paths: `/`, `/workspace/:workspaceId`, and `/workspace/:workspaceId/node/:nodeId`.
- Adjacent paths: WU-0A-01 router/provider scaffold, WU-0A-07 invoke command contract, WU-0A-11 pane taxonomy, and WU-0A-12 shell state parser.
- Migration path: additive frontend route/component/contract fixtures.
- Rollback path: remove the two workspace routes, workspace shell component, WU-0A-13 contract fixtures, and tests; restore the root route wrapper if no other child routes use it.
- Observability: visible `data-testid` indicators expose shell count, workspace ID, selected node ID, active pane, and serialized shell state.

## Assumptions

- A1: The existing router remains code-based. Evidence: `src/router.tsx` constructs routes manually. Invalidated by adding TanStack file-route generation.
- A2: Phase 0A runtime status must not invoke `ping_runtime`. Evidence: Rust registers only `subscribe_workspace_events` and the ticket forbids new Tauri commands. Invalidated by a prior WU registering `ping_runtime` in Rust.
- A3: Unknown pane fallback is a route-shell behavior, not a change to `parsePaneId`. Evidence: WU-0A-11 parser correctly rejects unknown panes. Invalidated by a contract revision requiring parser-level aliasing.
- A4: Provider/GraphStore/agents absence is observable at the frontend boundary through no Tauri invoke calls and no Node provider-file reads in tests. Invalidated by adding a frontend store that performs those actions during route render.

## Test Intent

- Route render invariant: render each workspace route and assert exactly one shell root plus copied params. Risk: route nesting duplicates shells or loses params. Level: component. Fixtures: WU-0A-13 route fixtures. Assumptions: A1.
- Pane query coverage: render each documented `PaneId` query and assert `ShellRegionState.activePane`. Risk: route search accepts only a subset of panes. Level: component and end-to-end. Fixtures: WU-0A-11 pane IDs and WU-0A-13 route fixtures. Assumptions: A3.
- Unknown-pane fallback: render `?pane=unknown` and assert `runtimeStatus` without mutation. Risk: bad search state leaks into the shell. Level: component and end-to-end. Fixtures: WU-0A-13 unknown-pane fixture. Assumptions: A3.
- Side-effect absence: render routes and assert no Tauri invoke for agents/provider/migrations and no provider config read. Risk: route render accidentally enters Phase 0B+ domains. Level: component/static boundary. Fixtures: side-effect absence fixture. Assumptions: A2, A4.
- Browser route smoke: Playwright loads the workspace route and query variants against Vite. Risk: component tests pass but browser routing fails. Level: end-to-end. Fixtures: WU-0A-11 pane IDs.
