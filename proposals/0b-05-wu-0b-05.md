# WU-0B-05 Proposal: GraphConfiguration

## Design

Add `GraphConfiguration` as the inert, versioned graph and memory configuration record. The Rust surface is repository code only:

```text
GraphConfiguration {
  configuration_id: OpaqueId<GraphConfiguration>,
  workspace_id: OpaqueId<GraphWorkspace>,
  configuration_version: i64,
  schema_profile: String,
  summary_contract_template_ids: JsonField<Vec<String>>,
  optimizer_policy_ref: OpaqueId<PolicySet>,
  render_policy_ref: OpaqueId<PolicySet>,
  memory_policy_ref: OpaqueId<PolicySet>,
  provider_routing_policy_ref: OpaqueId<PolicySet>,
  capability_fingerprint_policy_ref: OpaqueId<PolicySet>,
  effective_value_sources: JsonField<Vec<EffectiveValueSourceEntry>>,
  created_from_configuration_id: Option<OpaqueId<GraphConfiguration>>,
  validation_state: ValidationState,
  meta: RecordMeta
}

EffectiveValueSourceEntry {
  field_name: String,
  source: EffectiveValueSource,
  source_ref: String
}
```

`GraphWorkspace` is only an opaque marker in this WU. No `graph_workspaces` table or workspace FK is created before WU-0B-06. The five policy refs point at WU-0B-04 `policy_sets`.

`EffectiveValueSource` variants are `system_required`, `default`, `inherited`, `user_configured`, and `recovered`. `ValidationState` variants are `valid`, `valid_with_warnings`, `invalid_schema`, `invalid_provider_route`, `invalid_budget`, `invalid_index`, and `needs_user_attention`. Both enums derive serde string forms and implement SQLx `Type`, `Encode`, and `Decode` over SQLite `TEXT`.

## graph_configurations Table

`graph_configurations` columns:

- `row_id INTEGER PRIMARY KEY`
- `configuration_id_value TEXT NOT NULL`
- `configuration_id_namespace TEXT NOT NULL`
- `workspace_id_value TEXT NOT NULL`
- `workspace_id_namespace TEXT NOT NULL`
- `configuration_version INTEGER NOT NULL`
- `schema_profile TEXT NOT NULL`
- `summary_contract_template_ids TEXT NOT NULL CHECK (json_valid(summary_contract_template_ids))`
- ten policy-ref opaque columns, value plus namespace for each of the five refs
- `effective_value_sources TEXT NOT NULL CHECK (json_valid(effective_value_sources))`
- nullable `created_from_configuration_id_value` and `created_from_configuration_id_namespace`
- `validation_state TEXT NOT NULL`
- `created_at`, `updated_at`, `actor`, and `record_policy_version` RecordMeta columns
- `schema_version INTEGER NOT NULL DEFAULT 5 REFERENCES schema_versions(version)`
- `UNIQUE(configuration_id_value, configuration_id_namespace)`

Indexes:

- explicit lookup index on `(configuration_id_value, configuration_id_namespace)`
- workspace list index on `(workspace_id_value, workspace_id_namespace)`
- revision parent index on `(created_from_configuration_id_value, created_from_configuration_id_namespace)`

Each policy ref has a composite FK to `policy_sets(policy_set_id_value, policy_set_id_namespace)`. JSON columns use SQLite `json_valid` checks. The migration creates no table except `graph_configurations`.

## Validation

`insert_graph_configuration` validates opaque IDs, `RecordMeta`, non-empty `schema_profile`, positive `configuration_version`, non-empty template ids, and effective-value attribution. Every `EffectiveValueSourceEntry` requires non-empty `field_name` and `source_ref`; an empty or missing `source_ref` returns `GraphStoreError::InvariantViolation`.

The source vector must include attribution for the effective configuration fields:

- `configuration_version`
- `schema_profile`
- `summary_contract_template_ids`
- `optimizer_policy_ref`
- `render_policy_ref`
- `memory_policy_ref`
- `provider_routing_policy_ref`
- `capability_fingerprint_policy_ref`
- `validation_state`

Unknown enum strings are rejected by serde or SQLx decode with the documented invalid-enum path in tests.

## Append-Only Revisions

There are no update or upsert methods. A new revision is a new row with a new `configuration_id`.

`created_from_configuration_id` may be null. When non-null, the repository checks inside the insert transaction that the parent row exists, has the same workspace opaque ID, and has `created_at` smaller than the child row. Missing parent returns `UnknownRef`; wrong workspace or non-older parent returns `InvalidTransition`.

## Repository

`GraphConfigurationRepo` wraps a `SqlitePool`, implements `GraphStoreRepo<GraphConfiguration>`, and exposes:

- `insert_graph_configuration(record) -> Result<GraphConfiguration, GraphStoreError>`
- `get_graph_configuration(id) -> Result<Option<GraphConfiguration>, GraphStoreError>`
- `list_graph_configurations_by_workspace(workspace_id) -> Result<Vec<GraphConfiguration>, GraphStoreError>`

The trait `list_by_workspace` adapts WU-0B-03 `GraphWorkspaceRef` into this WU's `GraphWorkspace` marker without creating a workspace table.

## Transactions

`insert_graph_configuration` begins an explicit SQLite transaction before validation and commits only after all repository checks and the insert succeed. Validation failures, missing refs, FK failures, duplicate IDs, enum decode failures, and invalid revision transitions roll back and leave the row count unchanged.

## Anti-Scope

- No graph node, edge, workspace, snapshot, value-slice, command, registry, or UI table.
- No Tauri command or command registration.
- No operator-visible pane, subprocess launch, agents invocation, optimizer execution, provider probe, or recovery execution.

## Supported Surface

Deployment mode is additive SQLite migration plus inert Rust GraphStore repository code. Customer cohort remains local single-user harness development. Public/user-reachable paths remain the existing Phase 0A shell and `subscribe_workspace_events`; this WU adds no command or UI affordance. Adjacent blast radius is bounded to recursive migration application, GraphStore fixture runtime table assertions, and policy-set FK setup in contract tests. Migration path is additive through version 5. Rollback is code/database reset in the test harness; the migration framework still has no down migrations. Observability is direct contract-test inspection of schema, rows, errors, enum codecs, and command absence.

Net value: this supplies the durable configuration row required by later GraphWorkspace, snapshot, working-set, optimizer, and registry WUs while keeping behavior inert. The added blast radius is acceptable because the only new durable object is the declared table and all active policy behavior remains future-owned.

## Assumptions

- A1: `workspace_id` is an opaque ID without FK until WU-0B-06. Evidence: the ticket explicitly says WU-0B-06 ships `GraphWorkspace`. Invalidated by a revised dependency order that ships `graph_workspaces` first.
- A2: The policy refs must use composite opaque-id FKs into `policy_sets`, matching WU-0B-04 storage. Evidence: PolicySet stores value and namespace columns under a composite unique constraint. Invalidated by a WU-0B-04 schema change to a single scalar primary key.
- A3: Append-only is enforced at the repository boundary. Evidence: the WU asks for repository validation and no update statements. Invalidated by a revised requirement for SQLite triggers that block manual updates.
- A4: `schema_profile` is a non-empty string, not an enum, because the ticket names no variants. Evidence: the build request allows enum or string. Invalidated by a contract amendment listing schema-profile variants.

## Test Intent

- Schema creation. Risk: table misses columns, JSON checks, policy FKs, unique constraint, indexes, or RecordMeta fields. Level: particular-integration. Fixture source: `canonical-row.json`. Signal: `sqlite_master` and PRAGMA introspection expose the declared table shape.
- Round-trip. Risk: repository loses or rewrites scalar, enum, JSON, timestamp, or opaque-ID fields. Level: particular-integration. Fixture source: `round-trip.json`. Signal: insert then get serializes byte-equivalent to the fixture.
- Transaction rollback. Risk: FK, enum, source-attribution, or revision-transition failures leave durable rows. Level: particular-integration. Fixture source: FK, unknown-variant, source-attribution, and append-only fixtures. Signal: row count is unchanged and documented errors are returned.
- Side-effect absence. Risk: configuration storage enables operator-visible behavior. Level: component structural. Fixture source: side-effect assertions in the test. Signal: command allowlist remains unchanged and no forbidden runtime/process/UI tokens appear.
- Contract boundary. Risk: tests inspect future services outside the WU boundary. Level: component. Fixture source: this contract. Signal: tests import only graphstore fixture/prelude, policyset setup, graphconfiguration contracts/repo, and scaffold command allowlist.
- Effective source variants. Risk: one attribution source variant is unreachable or fails serde/SQLx round-trip. Level: unit/particular-integration. Fixture source: `effective-value-source-variants.json`. Signal: every variant round-trips and unknown values are rejected.
- Validation state variants. Risk: one validation state variant is unreachable or fails serde/SQLx round-trip. Level: unit/particular-integration. Fixture source: `validation-state-variants.json`. Signal: every variant round-trips and unknown values are rejected.
- Append-only revisions. Risk: configuration revisions overwrite history or link to the wrong parent. Level: particular-integration. Fixture source: `append-only-revision.json`. Signal: null first revision succeeds; second revision references an older same-workspace row; missing/different-workspace/non-older parents fail.
- Source attribution. Risk: effective values lack provenance. Level: particular-integration. Fixture source: `source-attribution-rejection.json`. Signal: missing or empty `source_ref` returns `InvariantViolation`.
