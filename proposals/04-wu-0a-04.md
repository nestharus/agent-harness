# WU-0A-04 Proposal: HarnessAppState Backend Container

## Design

Add a Rust-only `HarnessAppState` backend container that owns the Phase 0A runtime handles:

- `settings: HarnessSettings` as an owned DTO. It is small, cloneable, and remains the source of `workspace_id`.
- `storage_layout: LocalStorageLayout` as an owned DTO. It is small, cloneable, and remains the source of `storage_root` and `database_path`.
- `event_bus: EventBusHandle` as a cloneable handle over `tokio::sync::broadcast::Sender<IpcEvent<serde_json::Value>>`.
- `db: sqlx::SqlitePool` as sqlx's cloneable pool handle, opened against `storage_layout.database_path`.
- `trace_context_factory: TraceContextFactory` as a cloneable wrapper around the configured `workspace_id` that calls WU-0A-09 `create_trace_context(...)`.

`init_harness_app_state(settings, storage_layout)` validates settings and storage layout before opening resources, then opens SQLite, creates the event bus, and creates the trace-context factory.

## EventBusHandle Design

WU-0A-05 owns only the `EventTopic` taxonomy, and WU-0A-06 owns `IpcEvent<T>`. This WU owns the backend event-bus handle as a minimal broadcast sender for JSON-valued IPC events:

```text
EventBusHandle = cloneable wrapper over broadcast::Sender<IpcEvent<serde_json::Value>>
```

Phase 0A does not register commands or emit domain events from this WU. The handle only proves the backend state owns an event-stream primitive for WU-0A-08 and later slices.

Default event-bus initialization is infallible in normal runtime because it uses a fixed positive broadcast capacity. `EventBusInitFailed` is therefore reached through the documented test seam: `init_harness_app_state_with_factories(...)` accepts an injectable `EventBusFactory`, and the fixture factory returns failure.

## TraceContextFactory Design

WU-0A-09 owns `create_trace_context(...)`. This WU owns the app-state wrapper:

```text
TraceContextFactory { workspace_id: String }
TraceContextFactory::create(actor, invocation_id, parent_invocation_id, graph_ref, audit_event_ref)
```

The factory is cloneable and stores only the workspace ID needed to call `create_trace_context`. Default initialization fails only if the supplied workspace ID is invalid, which is already guarded by settings validation. `TraceInitFailed` is reached through the documented test seam: `init_harness_app_state_with_factories(...)` accepts an injectable trace factory initializer, and the fixture initializer returns failure.

## SQLite Pool

Open `sqlx::SqlitePool` against `storage_layout.database_path` with:

- `SqliteConnectOptions::new().filename(path)`
- `create_if_missing(true)` so fresh temp-fixture databases are accepted
- `SqlitePoolOptions::new().max_connections(1)` because Phase 0A only needs a real handle, not concurrency tuning

No migrations, GraphStore tables, or schema validation are run in this WU.

## BootstrapError Taxonomy

`BootstrapError` serializes as one of these exact strings:

- `SettingsInvalid`
- `StorageLayoutInvalid`
- `DatabaseOpenFailed`
- `EventBusInitFailed`
- `TraceInitFailed`

Failure injection:

- `SettingsInvalid`: construct `HarnessSettings` with an empty required field.
- `StorageLayoutInvalid`: construct `LocalStorageLayout` with a path outside the configured storage root.
- `DatabaseOpenFailed`: use a valid settings/layout pair whose database path cannot be opened as a SQLite file.
- `EventBusInitFailed`: call `init_harness_app_state_with_factories(...)` with a fixture `EventBusFactory` that fails.
- `TraceInitFailed`: call `init_harness_app_state_with_factories(...)` with a fixture trace initializer that fails.

Unknown `BootstrapError` variants are rejected by serde.

## Test Seam

Expose `init_harness_app_state_with_factories(settings, storage_layout, event_bus_factory, trace_context_factory_initializer)` at module level. Production callers use `init_harness_app_state(...)`, which supplies default factories. Contract tests use the factory variant only for the event-bus and trace-initialization failure fixtures.

## Anti-Scope

- No IPC commands registered; `registered_command_count() == 0` remains the invariant.
- No GraphStore migrations, tables, schemas, or repository abstractions.
- No provider credentials or provider configuration.
- No `agents` subprocess invocation.
- No Tauri command registration, invoke-handler edits, or `tauri.conf.json` command additions.

## Supported Surface

- Deployment mode: local Phase 0A Tauri backend library and desktop scaffold.
- Customer cohort: internal contract consumers and future Phase 0A slices importing app state.
- Public paths: Rust library consumers of `app_state` and `contracts::harness_app_state`.
- Adjacent paths in blast radius: settings validation, storage layout validation, event and trace DTO modules, sqlx dependency use, and the command-free Tauri scaffold invariant.
- Migration path: additive Rust module, additive contract module, fixtures, and tests.
- Rollback path: remove the added app-state module, contract module, fixtures, tests, proposal, and module declarations.
- Observability: Rust contract tests expose happy-path handle creation, each bootstrap failure variant, serde round-trip, and the no-command invariant.

## Assumptions

- A1: `HarnessSettings` required fields are the non-empty strings validated by WU-0A-02: `workspace_id`, `storage_root`, `database_path`, and `agent_runner_bin`. Evidence: `src-tauri/src/settings.rs`. Invalidated by a revised settings contract that changes required fields.
- A2: Storage-layout containment remains lexical and is delegated to WU-0A-03 validation. Evidence: `src-tauri/src/storage.rs`. Invalidated by a revised storage contract requiring canonical filesystem checks or symlink policy.
- A3: Phase 0A needs a real SQLite file handle but no schema. Evidence: WU-0A-04 anti-scope and Phase 0B outgoing GraphStore dependencies. Invalidated by a revised WU requiring migrations or table presence.
- A4: Event bus and trace factory default initialization should not need artificial runtime tokens. Evidence: WU-0A-05 and WU-0A-09 own the reusable DTO/helper contracts, while WU-0A-04 owns only the container handle. Invalidated by a revised event or trace WU that adds mandatory backend configuration.

## Test Intent

- Happy-path app-state initialization: verify all five handles are created and `workspace_id`, `storage_root`, and `database_path` are preserved. Risk: container wiring drops or mutates owned subsystem handles. Level: particular-integration. Fixture: `happy-path.json`. Assumptions: A1, A2, A3.
- Settings validation error: verify empty required settings fields map to `BootstrapError::SettingsInvalid` before resource opening. Risk: invalid settings reach runtime handles. Level: unit. Fixture: `error-settings-invalid.json`. Assumption: A1.
- Storage layout validation error: verify outside-root layout paths map to `BootstrapError::StorageLayoutInvalid` before resource opening. Risk: invalid layout reaches SQLite. Level: unit. Fixture: `error-storage-layout-invalid.json`. Assumption: A2.
- SQLite open error: verify an unopenable in-root database path maps to `BootstrapError::DatabaseOpenFailed`. Risk: database failure is hidden or misclassified. Level: particular-integration. Fixture: `error-database-open-failed.json`. Assumption: A3.
- Event bus factory error: verify fixture factory failure maps to `BootstrapError::EventBusInitFailed`. Risk: test-only event seam cannot prove documented taxonomy. Level: unit. Fixture: `error-event-bus-init-failed.json`. Assumption: A4.
- Trace factory error: verify fixture trace initializer failure maps to `BootstrapError::TraceInitFailed`. Risk: test-only trace seam cannot prove documented taxonomy. Level: unit. Fixture: `error-trace-init-failed.json`. Assumption: A4.
- BootstrapError serde: verify every variant round-trips and an unknown variant rejects. Risk: Rust error taxonomy drift. Level: particular-integration. Fixtures: `bootstrap-errors.json`, `invalid-bootstrap-error.json`.
