# WU-0A-01 Proposal: Repository Workspace and Runtime Scaffold

## Design

Create the Phase 0A repository foundation as an inert desktop shell. The workspace will use Bun for package management, Turbo for task orchestration, Vite for a React 19 SPA under `src/`, Tauri v2 under `src-tauri/`, Rust with Tokio, sqlx compiled for SQLite readiness, Tailwind v4 CSS-first styling, TanStack Router for one inert root route, and TanStack Query for the provider boundary.

The shell will expose a visible application root only. It will not invoke `agents`, require provider credentials, create GraphStore tables, or claim operator-visible product behavior beyond successful startup.

## Scope

- Add root workspace, task-runner, TypeScript, Vite, Tailwind, ESLint, Vitest, and Playwright configuration.
- Add `src/` React shell with TanStack Router and TanStack Query providers.
- Add `src-tauri/` Tauri v2 shell with Rust/Tokio/sqlx-ready dependencies and inert bootstrap code.
- Add contract fixtures and tests for the scaffold shape.
- Add empty placeholder migration directory only if needed for the future location; do not add migration files.

## Architecture

- The root package is the only workspace package for Phase 0A, keeping the frontend and Tauri shell colocated at the repository root as required by the ticket.
- Turbo runs named internal tasks for frontend build/test/lint/typecheck and Rust check/clippy/build surfaces.
- Tauri owns only a no-command bootstrap entrypoint. `src-tauri/src/lib.rs` exposes `run()` and a compile-time testable `registered_command_count()` returning `0`.
- The frontend shell exports its root component for Vitest and uses the same route tree in production and tests.
- Contract fixtures under `product-strategy/contracts/fixtures/wu-0a-01/` define canonical package, Turbo, and Tauri shapes used by the Rust contract test.

## Tradeoffs

- A single root package keeps this WU small and matches the requested `src/` and `src-tauri/` paths, at the cost of less package isolation than a later multi-app monorepo.
- The contract test checks a strict dependency and config subset instead of comparing full generated lockfiles, avoiding churn while still pinning the scaffold boundary.
- sqlx is included as a dependency with SQLite and Tokio runtime features, but no migrations are introduced.

## Anti-Scope

- No GraphStore migrations, durable schema objects, or database initialization.
- No provider configuration, OAuth flow, API key loading, or credential validation.
- No real `agents` subprocess invocation.
- No value-slice commands, event models, agent orchestration, memory features, or product claims beyond a running shell.
- No Phase 0B or Phase 0C implementation content.

## Supported-Surface Track

- Deployment mode: local developer workstation only, through Bun, Vite, Playwright, Cargo, and Tauri CLI commands.
- Customer cohort: internal developers preparing the repository for later Phase 0A slices.
- Adjacent paths: planning and research files remain read-only except for the new proposal and contract artifacts; future GraphStore paths are represented only by an empty migration directory.
- Blast radius: package/task configuration affects all local quality commands, but no existing runtime surface exists in this greenfield worktree.
- Migration: no data migration and no durable schema. Later WUs can add migrations in the established location without moving the scaffold.
- Rollback: remove the added scaffold/configuration files and contract artifacts; no user data or schema rollback is required.
- Observability: command success/failure, Vitest DOM assertion, Playwright visible-root assertion, Rust contract test output, Cargo check/clippy, and Tauri startup/build logs.

## Existing-State Risk Profile

N/A for existing runtime behavior. The current worktree has planning/research artifacts and no application scaffold, no supported runtime route, and no customer-reachable application path. This WU creates the surface rather than modifying an existing one.

## Qualitative Net Value

The proposal reduces the concrete current-state risk that later Phase 0A work has no stable repository/runtime target to attach to. Because the scaffold has no durable schema, no credentials, and no value-slice behavior, that value outweighs the added local-build blast radius and has a simple rollback path.

## Assumption Register

- A1: Greenfield runtime surface.
  - Evidence: `git show tickets-phase-0a:plans/tickets/phase-0a/WU-0A-01.md` identifies this ticket as the foundation scaffold with no earlier Phase 0A dependency; the worktree contains only planning/research files.
  - Invalidator: discovery of an existing app/runtime entrypoint in the worktree that this scaffold would replace or conflict with.
- A2: Root colocated scaffold is required.
  - Evidence: ticket code boundary names root files, `src/**/*`, and `src-tauri/**/*` directly.
  - Invalidator: an approved architecture artifact requiring `apps/*` or package-level relocation before Phase 0A scaffolding.
- A3: sqlx-ready means dependency readiness, not schema ownership.
  - Evidence: ticket contract says SQLite/sqlx-ready and separately says no durable schema object is owned by this WU.
  - Invalidator: a later approved contract requiring this WU to create migrations or tables.
- A4: Phase 0A inert bootstrap may register no Tauri commands.
  - Evidence: acceptance criteria allow no value-slice commands beyond Phase 0A-owned inert bootstrap commands.
  - Invalidator: approved Phase 0A contract requiring a specific bootstrap command.

## Test-Intent Track

- Contract fixture shape.
  - Change risk: workspace drift or accidental Phase 0B/0C content entering the scaffold.
  - Intended behavior: `package.json`, `turbo.json`, `Cargo.toml`, `tauri.conf.json`, and bootstrap files match the canonical Phase 0A shape.
  - Level: particular-integration.
  - Fixture source: `product-strategy/contracts/fixtures/wu-0a-01/`.
  - Assumption link: A2, A3, A4.
  - Expected signal: Rust contract test passes and fails on missing pinned dependencies, Tauri config drift, migrations, or command registration.
  - Residual risk: does not prove every OS-specific Tauri bundle dependency is installed.
- React shell smoke.
  - Change risk: shell route accidentally depends on GraphStore, provider credentials, or `agents`.
  - Intended behavior: root shell renders a visible application root in DOM.
  - Level: component.
  - Fixture source: test runner DOM environment; no external fixture state.
  - Assumption link: A1.
  - Expected signal: Vitest and Testing Library find the application root.
  - Residual risk: does not exercise native webview startup.
- Inert route e2e.
  - Change risk: browser-served frontend does not expose a reachable inert root route.
  - Intended behavior: Playwright launches the route and verifies the visible application root.
  - Level: end-to-end.
  - Fixture source: Playwright web server using `bun run frontend:dev`.
  - Assumption link: A1.
  - Expected signal: Playwright locator for `[data-testid="app-root"]` is visible.
  - Residual risk: browser e2e does not prove Tauri native shell opens on every desktop environment.
- Local quality commands.
  - Change risk: quality commands bypass one side of the workspace.
  - Intended behavior: lint/typecheck/build/test scripts execute through Turbo and cover TypeScript and Rust surfaces.
  - Level: particular-integration.
  - Fixture source: root `package.json` and `turbo.json` fixtures.
  - Assumption link: A2.
  - Expected signal: `bun run lint`, `bun run typecheck`, `cargo fmt --check`, and `cargo clippy` fail on relevant scaffold regressions.
  - Residual risk: does not certify future packages not yet present in the workspace.
