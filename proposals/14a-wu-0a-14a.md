# WU-0A-14a Proposal: Temp SQLite Harness Entrypoint

## Design

Add a Rust-only `temp_harness_state(seed_name, settings?, storage_layout?, runtime_event_fixtures?)` builder in `src-tauri/src/test_harness/temp_harness.rs`. The builder composes the existing Phase 0A settings, storage layout, app-state, IPC envelope, subscription, and backend span contracts into an isolated temp SQLite harness for Rust tests and dev scripts.

The builder uses an internal seed registry keyed by documented seed names. The initial registry contains:

- `empty`: creates an isolated workspace with no runtime fixture events.
- `minimal-runtime`: creates an isolated workspace intended for runtime event fixture replay.
- `missing-manifest`: intentionally points at absent fixture manifest metadata to exercise `FixtureManifestMissing`.

For each call, the seed registry derives a unique temp directory, `HarnessSettings`, `LocalStorageLayout`, and fixture manifest metadata path. If `settings` or `storage_layout` are `None`, the derived seed values are used. If either is `Some`, the supplied value is used verbatim for that side of the contract.

## TempHarnessHandle

`TempHarnessHandle` is the stable serializable DTO returned by `temp_harness_state`:

- `workspace_id`: the effective settings workspace ID.
- `database_path`: a real SQLite file path under a unique-per-call temp directory unless the caller supplied a different storage layout.
- `fixture_manifest_id`: a seed-derived manifest identifier, formatted from the seed name and a per-call timestamp/counter.
- `app_state_ready`: `true` only after `init_harness_app_state` returns `Ok`.

The live `HarnessAppState` is not part of the DTO because it owns non-serializable runtime handles. A Rust-only lookup seam retrieves the initialized state for tests/dev scripts from a `TempHarnessHandle`.

## TempHarnessError

`TempHarnessError` has exactly five variants:

- `UnknownSeed`: `seed_name` is not present in the seed registry.
- `DatabaseCreateFailed`: the harness SQLite create/open probe fails before app-state initialization, such as when the effective `database_path` is already a directory or its parent cannot be created.
- `AppStateInitFailed`: `init_harness_app_state` returns `Err` after the SQLite create/open probe succeeds.
- `RealAgentsInvocationAttempted`: the documented spawn-attempt seam `attempt_real_agents_spawn(&TempHarnessHandle)` is called. The harness refuses structurally and never executes `/home/nes/.local/bin/agents`.
- `FixtureManifestMissing`: the selected registered seed points at manifest metadata that does not exist.

## Runtime Event Fixtures

`runtime_event_fixtures` is an array of `BackendSpanEvent` payloads. Phase 0A remains passive: no domain producer runs. The harness records these payloads as runtime-topic fixture envelopes associated with the handle. Tests can create a runtime-topic bus subscriber and call the documented replay seam to publish the recorded fixture envelopes through the existing event bus.

## No GraphStore Migrations

The harness must not invoke `sqlx::migrate!`, define a `MIGRATIONS_DIR` constant, or run schema DDL. SQLite access is limited to `create_if_missing` open/probe behavior and the existing `init_harness_app_state` open path. The resulting database has no user tables.

## Anti-Scope

- No new Tauri commands; `phase_0a_scaffold_commands()` remains exactly `["subscribe_workspace_events"]`.
- No real `/home/nes/.local/bin/agents` invocation.
- No provider credentials.
- No GraphStore DDL or migrations.
- No frontend renderer work; WU-0A-14b owns React renderer concerns.

## Supported Surface

- Deployment mode: Rust library/test harness only.
- Customer cohort: internal tests and development scripts.
- Adjacent public paths: existing `init_harness_app_state`, event bus subscription handles, backend span DTOs, and scaffold command registration invariant.
- Blast radius: Rust module declarations and test-only harness helpers. Existing Tauri command list and frontend source remain unchanged.
- Migration path: additive Rust contract and test harness module.
- Rollback path: remove the new proposal, contract doc, fixtures, Rust contract module, test harness module, module declarations, and contract test.
- Observability: tests assert returned handle fields, SQLite file presence, empty schema, app-state event-bus usability, runtime fixture replay, and every error path.

## Assumptions

- A1: `init_harness_app_state` remains the correct Phase 0A initializer for live runtime handles. Evidence: WU-0A-04 owns `HarnessAppState` and already exposes a reusable factory seam. Invalidated by a revised app-state ownership contract.
- A2: Phase 0A SQLite creation must not imply GraphStore schema setup. Evidence: the ticket explicitly forbids migrations and GraphStore DDL. Invalidated by a future phase making migrations part of harness creation.
- A3: The serializable handle must stay minimal and omit live runtime handles. Evidence: the WU contract lists only four `TempHarnessHandle` fields. Invalidated by a revised WU contract adding app-state fields to the DTO.

## Test Intent

- DTO serde round-trip: verify `TempHarnessHandle` preserves the four stable field names. Risk: Rust contract drift. Level: particular-integration. Fixtures: `handle-round-trip.json`. Assumption: A3.
- Seed happy paths: verify every documented happy seed returns a non-empty handle and `app_state_ready == true`. Risk: registry drift. Level: particular-integration. Fixtures: `seed-registry.json`, per-seed happy fixtures.
- App-state composition: verify the handle resolves to a live `HarnessAppState` whose event bus can broadcast fixture runtime events. Risk: bypassing WU-0A-04. Level: particular-integration. Fixtures: runtime replay fixture. Assumption: A1.
- SQLite isolation and no migrations: verify the database file exists and `sqlite_master` contains no tables. Risk: accidental GraphStore setup. Level: particular-integration. Assumption: A2.
- Error taxonomy: verify all five `TempHarnessError` variants round-trip and are reachable through documented fixtures/seams. Risk: unreachable or renamed error surface. Level: unit/particular-integration. Fixtures: per-error fixtures.
- Real agents refusal: verify `attempt_real_agents_spawn` returns `RealAgentsInvocationAttempted`. Risk: accidental binary execution. Level: unit. Fixture: no-agents assertion.
- Scaffold invariant: verify `phase_0a_scaffold_commands()` remains a single `subscribe_workspace_events` command. Risk: command leakage. Level: particular-integration.
