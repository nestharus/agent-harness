# WU-0B-15 AuditEvent Proposal

## Scope

`AuditEvent` adds an append-only local record for decisions and state changes. This WU owns only the GraphStore schema, typed Rust contract, repository insert/get/list boundary, contract fixtures, and contract tests.

Anti-scope: no provider state table or FK target, no audit-trail UI, no commands, no agent launch, no provider probe, no optimizer execution, and no recovery execution.

## Row

```text
AuditEvent {
  audit_event_id: OpaqueId<AuditEvent>,
  workspace_id: OpaqueId<GraphWorkspace>,
  event_type: String,
  actor: String,
  policy_set_id: OpaqueId<PolicySet>,
  configuration_id: Option<OpaqueId<GraphConfiguration>>,
  provider_state_id: Option<OpaqueId<ProviderStateRef>>,
  input_refs: JsonField<Vec<String>>,
  output_refs: JsonField<Vec<String>>,
  decision: AuditDecision,
  reason_code: String,
  created_at: Timestamp,
  meta: RecordMeta
}
```

`event_type` is an open enum represented as a non-empty string. Phase 0B has no stable cross-slice event taxonomy yet, so this WU scopes the vocabulary to fixtures and callers while preserving forward compatibility for later values.

`provider_state_id` is a soft reference because WU-0B-17 owns the provider state target. It is validated as an `OpaqueId` when present but has no FK in this WU.

The database stores domain `actor` and `created_at` as `actor` and `created_at`. `RecordMeta` is stored under `record_created_at`, `record_updated_at`, `record_actor`, and `record_policy_version` to avoid name collisions.

## Decision Enum

`AuditDecision` is encoded as SQLite text through `impl_sqlite_text_enum!` and serde `snake_case`:

- `accepted`
- `rejected`
- `deferred`
- `quarantined`
- `user_required`

Unknown decision values are rejected by serde and SQLx decode.

## Schema

Create exactly one durable table: `audit_events`.

Columns:

- opaque IDs split into value/namespace columns for `audit_event_id`, `workspace_id`, `policy_set_id`, optional `configuration_id`, and optional soft `provider_state_id`
- `event_type`, `actor`, `decision`, `reason_code`, `created_at`
- `input_refs` and `output_refs` as JSON text arrays
- `record_created_at`, `record_updated_at`, `record_actor`, `record_policy_version`
- `schema_version` defaulting to 15

Constraints:

- `UNIQUE(audit_event_id_value, audit_event_id_namespace)`
- FKs to `graph_workspaces`, `policy_sets`, optional `graph_configurations`, and `schema_versions`
- paired-null checks for optional configuration/provider IDs
- JSON validity checks for `input_refs`, `output_refs`, and `record_actor`
- decision CHECK over the five variants

Indexes:

- `idx_audit_events_workspace_id`
- `idx_audit_events_policy_set_id`
- `idx_audit_events_decision`
- `idx_audit_events_created_at`

## Repository

- `insert_audit_event(AuditEvent) -> Result<AuditEvent, GraphStoreError>`
- `get_audit_event(&OpaqueId<AuditEvent>) -> Result<Option<AuditEvent>, GraphStoreError>`
- `list_audit_events_by_workspace(&OpaqueId<GraphWorkspace>) -> Result<Vec<AuditEvent>, GraphStoreError>`

Writes run inside an explicit transaction and roll back on validation, duplicate ID, enum, or FK failures.

## Invariants

Append-only: the repository exposes only insert and read paths. It contains no `UPDATE audit_events` or `DELETE FROM audit_events` statements. The contract test asserts this by source grep.

Output-with-input: if `output_refs` is non-empty, `input_refs` must contain at least one entry and `policy_set_id`, `actor`, `decision`, and `reason_code` must be present and non-empty where representable by the typed API. Violations return `GraphStoreError::InvariantViolation` or are rejected by SQLite NOT NULL/CHECK constraints for raw storage attempts.

All string refs inside `input_refs` and `output_refs` must be non-empty after trimming.

## Test Intent

- Schema creation: verify columns, FKs, unique constraint, JSON checks, and indexes. Level: particular-integration.
- Round-trip: insert/get byte-equivalent serde row including optional IDs, JSON refs, enum, timestamps, and `RecordMeta`. Level: particular-integration.
- Transaction rollback: FK and invariant failures leave no partial audit rows. Level: particular-integration.
- Side-effect absence: no new commands and only one new table. Level: component structural.
- Contract boundary: tests use only declared contract/repository surfaces and predecessor WU fixtures. Level: component structural.
- Decision variants: all five serde/SQLx variants round-trip and are reachable through insert; unknown decision rejected. Level: unit/particular-integration.
- Append-only: source contains no update/delete path for `audit_events`. Level: component structural.
- Output-with-input invariant: non-empty outputs require inputs plus policy/actor/decision/reason. Level: particular-integration.
- FK rejection: unknown workspace, policy set, or configuration rejects insert without partial writes. Level: particular-integration.
