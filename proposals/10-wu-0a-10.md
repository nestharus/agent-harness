# WU-0A-10 Proposal: BackendSpanEvent Runtime Event

## Design

Add a narrow runtime tracing event contract shared by Rust and TypeScript:

- Rust owns `BackendSpanEvent`, `BackendSpanStatus`, and `BackendSpanError` in `src-tauri/src/contracts/backend_span_event.rs`.
- Rust behavior lives in `src-tauri/src/tracing/backend_span_event.rs`, including `emit_backend_span(...)`.
- The runtime-topic envelope helper lives in `src-tauri/src/events/runtime_events.rs` and binds `BackendSpanEvent` payloads to `EventTopic::Runtime`.
- TypeScript mirrors the DTO, status union, error union, and runtime parser in `src/contracts/backend-span-event.ts`.
- Contract fixtures under `product-strategy/contracts/fixtures/wu-0a-10/` are the cross-language source of truth for success shapes, status names, error names, and the runtime-only topic example.

`BackendSpanEvent` contains a full nested `TraceContext`. The builder validates the supplied context against the WU-0A-09 contract invariants before returning an event. It preserves caller-supplied span name, timestamps, status, and optional error reference, and generates a non-empty opaque `span_event_id`.

## Status And Timestamp Invariants

- `started` requires `completed_at == None` and `error_ref == None`. Extra values for these fields are ignored by the builder output for a started span because no error variant exists for surplus started metadata in the WU contract.
- `completed` requires `completed_at >= started_at`; violation returns `BackendSpanError::CompletedBeforeStarted`.
- `failed` requires `error_ref`; violation returns `BackendSpanError::FailedWithoutErrorRef`.
- Empty `span_name` returns `BackendSpanError::EmptySpanName`.
- Invalid nested trace context returns `BackendSpanError::TraceContextInvalid`.

The timestamp comparison supports the Phase 0A documented timestamp surfaces: unix-nanos strings compare numerically when both values are decimal digits, and normalized RFC3339 strings compare lexically for contract fixtures. This WU does not introduce timestamp parsing errors because the WU error taxonomy has no invalid timestamp variant.

## TraceContext Nesting

The event carries the full WU-0A-09 `TraceContext` object, not just a trace id. `TraceContextInvalid` is returned when the supplied object fails WU-0A-09's contract checks: empty generated correlation id, empty workspace id, or `parent_invocation_id` without `invocation_id`. Actor validity is already enforced by the Rust `TraceActor` enum and by TypeScript parsing.

## Runtime-Only Topic Invariant

This WU constructs the `BackendSpanEvent` struct, its builder, and a canonical runtime envelope helper. It does not emit to the event bus and does not wire any producer. Producer wiring belongs to a later WU.

The runtime-only-topic test is static and structural: this WU's source files may reference `EventTopic::Runtime` when constructing example `IpcEvent<BackendSpanEvent>` envelopes and must not reference graph, render, provider, optimizer, worker, question, recovery, budget, or audit topic variants for backend span payloads.

## BackendSpanError Taxonomy

- `EmptySpanName`
- `CompletedBeforeStarted`
- `FailedWithoutErrorRef`
- `TraceContextInvalid`

## Anti-Scope

- No real event-bus emission or producer wiring.
- No IPC command registration; `phase_0a_scaffold_commands()` remains one command: `subscribe_workspace_events`.
- No graph, render, provider, worker, recovery, budget, audit, optimizer, or question topic payloads.
- No GraphStore tables or migrations.
- No provider credentials.
- No real `agents` invocation.

## Supported Surface

- Deployment mode: local Phase 0A Tauri scaffold and library contract tests.
- Customer cohort: internal contract consumers and future Phase 0A runtime producers.
- Public paths: Rust library consumers, TypeScript contract importers, and later event producer wiring.
- Adjacent paths in blast radius: existing event topic, IPC envelope, trace context, module declarations, and `bun run *` / Cargo checks.
- Migration path: additive contract, tracing module, runtime envelope helper, fixtures, and tests.
- Rollback path: remove the added BackendSpanEvent modules, fixtures, contract doc, proposal, and module declarations.
- Observability: Rust contract tests and Vitest tests expose DTO drift, status drift, builder invariant regressions, and topic-binding drift.

## Assumptions

- A1: Span event IDs are opaque non-empty strings generated by the Rust builder. Evidence: WU contract names `span_event_id: string` and acceptance criteria require preservation, not UUID format. Invalidated by a revised WU requiring a durable or externally meaningful id format.
- A2: Timestamp strings remain opaque except for completed-before-started ordering. Evidence: WU contract has no invalid timestamp error variant. Invalidated by a revised WU adding timestamp parse errors or timezone normalization requirements.
- A3: Runtime-only-topic enforcement is structural in this WU because no producer is wired. Evidence: ticket says this WU does not actually emit events to the bus. Invalidated by a revised WU requiring bus publication in scope.

## Test Intent

- Rust DTO shape and serde round-trip: verify fixed started, completed, failed, and runtime-envelope fixtures. Risk: Rust/TS contract drift. Level: particular-integration. Fixtures: `started-happy-path.json`, `completed-happy-path.json`, `failed-happy-path.json`, `runtime-only-topic-event.json`. Assumptions: A1, A3.
- Rust status taxonomy: verify every documented `BackendSpanStatus` variant serializes/deserializes exactly and is reachable through a documented builder input. Risk: status taxonomy drift. Level: particular-integration. Fixture: `backend-span-statuses.json`.
- Rust builder success behavior: verify started omits completion and error fields, completed preserves ordered timestamps, and failed preserves `error_ref`. Risk: builder drops or invents status-specific fields. Level: unit. Fixtures: started/completed/failed happy-path fixtures. Assumptions: A1, A2.
- Rust error reachability: verify all four `BackendSpanError` variants are reachable through documented builder inputs, including invalid TraceContext delegation to WU-0A-09. Risk: unreachable or renamed error surface. Level: unit. Fixtures: `error-*.json`, `backend-span-errors.json`.
- Runtime-only topic binding: verify the helper wraps backend span payloads with `runtime` and static source scanning finds no other `EventTopic` variants in WU-0A-10 source files. Risk: Phase 0A accidentally creates later-domain payloads. Level: particular-integration/static. Fixture: `runtime-only-topic-event.json`. Assumption: A3.
- TypeScript DTO and parser parity: verify TypeScript accepts fixture-shaped events, rejects malformed shapes, keeps status and error unions aligned, and parses runtime envelopes through the generic IPC parser. Risk: TypeScript accepts values Rust rejects. Level: unit/typecheck. Fixtures: WU-0A-10 fixtures.
