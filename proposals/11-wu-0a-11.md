# WU-0A-11 Proposal: PaneId Taxonomy

## Design

Add a TypeScript-only `PaneId` taxonomy for the Phase 0A single-tab shell. The contract surface lives in `src/contracts/pane-id.ts` and exposes:

- the exact `PaneId` union and canonical ordered `PANE_IDS` constant;
- the exact `PaneIdError` union and parser result type;
- `parsePaneId(raw)`, an exact-match parser that returns a success or documented error result without trimming, case folding, aliasing, or prefix matching.

Shell Phase 0A state lives in `src/shell/pane-id.ts`. It marks `runtimeStatus` as the only live pane and all other documented panes as inert placeholders. `ShellRoot` may read this metadata, but Phase 0A must not seed or claim real domain data for initiative maps, focus state, working sets, configuration, providers, questions, workers, optimizer logs, evidence, cost, or recovery.

## Scope

- Preserve the documented pane strings exactly: `initiativeMap`, `currentFocus`, `workingSetInspector`, `configurationInspector`, `providerPanel`, `questionQueue`, `workerBoard`, `optimizerLog`, `evidenceDrilldown`, `costSurface`, `recoverySurface`, and `runtimeStatus`.
- Return `EmptyPaneId` for `parsePaneId("")`.
- Return `UnknownPaneId` for every other undocumented string.
- Keep `runtimeStatus` as the only Phase 0A live pane.
- Keep every non-`runtimeStatus` pane present but inert.

## Anti-Scope

- No GraphStore, seeded graph data, provider probes, question routing, worker launch, optimizer queue, evidence browser, cost ledger, or recovery implementation.
- No Rust contract or Tauri command changes.
- No multi-tab navigation, route expansion, or pane-specific feature UI.

## Supported Surface

- Deployment mode: local Phase 0A desktop scaffold.
- Customer cohort: developer/test harness consumers only.
- Public paths: TypeScript contract importers and the React shell root.
- Adjacent paths: existing router, app shell, settings, event-topic, and trace-context contracts remain unchanged.
- Migration path: additive contract, shell metadata, fixtures, tests, and shell-root metadata wiring.
- Rollback path: remove the WU-0A-11 files and the additive `ShellRoot` metadata read.
- Observability: Vitest verifies fixture parity, parser success/error behavior, and live-vs-inert Phase 0A pane gating.

## Assumptions

- A1: Phase 0A has no real pane data except runtime scaffold status. Evidence: ticket acceptance criteria says only `runtimeStatus` may display live runtime scaffold state. Invalidated by a revised WU contract adding another live Phase 0A pane.
- A2: Pane parsing is exact-match against documented strings. Evidence: contract lists string variants and only `EmptyPaneId`/`UnknownPaneId` errors. Invalidated by a revised contract requiring normalization or aliases.
- A3: TypeScript-only fixtures are sufficient for this WU. Evidence: ticket code boundary is TypeScript-only and forbids Rust changes unless minimally required. Invalidated by a revised handoff requiring Rust serialization parity.

## Test Intent

- TypeScript taxonomy parity: verify `PANE_IDS` exactly matches the canonical fixture and the union rejects undocumented strings at type level. Risk: TypeScript accepts pane strings outside the WU contract. Level: unit/typecheck. Fixtures: `pane-ids.json`.
- Parser success behavior: verify every documented pane string returns a successful `PaneId` result. Risk: documented shell pane identifiers cannot be parsed by callers. Level: unit. Fixture: `parse-success.json`.
- Parser error behavior: verify empty and unknown raw strings return the documented error result shape. Risk: unknown pane identifiers silently enter shell state. Level: unit. Fixture: `parse-errors.json`.
- Phase 0A live/inert gating: verify `runtimeStatus` is the only live pane and all other pane identifiers are inert placeholders. Risk: Phase 0A UI claims unseeded domain data. Level: unit. Fixtures: `phase-0a-live-panes.json`, `inert-panes.json`.
