# WU-0B-01 Proposal: SQLite Migration Framework and schema_versions Tracking

## Design

Add a Rust GraphStore migration module at `src-tauri/src/graphstore/migrations.rs` and expose it through `pub mod graphstore;`. The runner is directory-driven and hand-rolled rather than backed by `sqlx::migrate!`.

The hand-rolled choice keeps the Phase 0A `sqlx` feature set unchanged and avoids compile-time migration embedding while Phase 0B is still assigning one migration file per work unit. The runner reads `src-tauri/migrations/NNNN_<name>.sql` style files from a supplied directory, validates that every version is positive and strictly increasing by version, computes a SHA-256 checksum over the exact file bytes, applies unapplied migrations in a SQLite transaction, and records each successful file in `schema_versions`.

Parsing rules:

- File extension must be `.sql`.
- File stem must contain one underscore.
- The prefix before the first underscore is a positive base-10 integer version.
- The suffix after the first underscore is the migration name and must be non-empty.
- Versions must be unique and strictly increasing after sorting by numeric version.
- Already-applied versions must match both `migration_name` and checksum.
- If a lower missing version appears after a higher version is already recorded, the runner rejects it as out-of-order before applying it.

`src-tauri/migrations/0001_schema_versions.sql` is the bootstrap migration. It creates only `schema_versions`; the runner records version 1 after that DDL succeeds.

## schema_versions

`schema_versions` shape:

- `version INTEGER PRIMARY KEY`
- `migration_name TEXT NOT NULL`
- `applied_at TEXT NOT NULL`
- `checksum TEXT NOT NULL`
- `execution_ms INTEGER NOT NULL`
- `applied_by TEXT NOT NULL`
- `rollback_state TEXT NOT NULL CHECK (rollback_state IN ('applied', 'rollback_unsupported', 'rollback_planned', 'rollback_failed'))`

`applied_at` is stored as SQLite UTC text from `strftime('%Y-%m-%dT%H:%M:%fZ','now')`. `applied_by` is the stable actor string `agent-harness-migrator`.

## DTOs

`MigrationRecord` matches the row layout exactly:

```text
MigrationRecord { version: i64, migration_name: String, applied_at: String, checksum: String, execution_ms: i64, applied_by: String, rollback_state: MigrationRollbackState }
```

`MigrationRollbackState` has four serde/sqlx text variants:

- `applied`
- `rollback_unsupported`
- `rollback_planned`
- `rollback_failed`

Unknown rollback states are rejected during serde and SQL row decoding.

`MigrationReport` carries:

```text
MigrationReport { applied_versions: Vec<i64>, skipped_versions: Vec<i64>, failed_version: Option<i64>, checksum_mismatches: Vec<i64>, rollback_state: MigrationRollbackState }
```

`MigrationError` taxonomy:

- `OutOfOrderVersion`
- `VersionChecksumMismatch`
- `VersionAlreadyAppliedDifferently`
- `RollbackUnsupported`
- `SqlxFailure`

Primary API:

```text
run_migrations(pool, migrations_dir) -> Result<MigrationReport, MigrationError>
```

The module also exposes `rollback_migration(pool, version) -> Result<(), MigrationError>` only to make the documented unsupported-rollback path explicit. WU-0B-01 does not implement rollback DDL and does not rewrite applied history.

## Idempotency and Checksums

Re-running with identical migration files produces a report with empty `applied_versions`, populated `skipped_versions`, no checksum mismatches, and no updates to `schema_versions`. Changing an already-applied file with the same version and name returns `VersionChecksumMismatch` and leaves rows unchanged. Reusing an applied version with a different migration name returns `VersionAlreadyAppliedDifferently`.

Checksums use SHA-256 over exact migration file contents.

## Phase 0A Scaffold Contract Update

The existing Phase 0A scaffold contract rejected `sqlx` migration ownership and required the migrations directory to be empty. This WU keeps `sqlx`'s `migrate` feature disabled by using a hand-rolled runner, so the feature assertion remains valid. The migrations-directory assertion changes from "empty placeholder only" to "may contain only `0001_schema_versions.sql` during WU-0B-01". Command allowlist assertions stay unchanged: `phase_0a_scaffold_commands()` remains exactly `["subscribe_workspace_events"]`.

This assertion change should be included in review scope as a bounded Phase 0A scaffold-contract update.

## Anti-Scope

- No Phase 0B domain tables beyond `schema_versions`.
- No new Tauri commands; `phase_0a_scaffold_commands()` count stays at 1.
- No provider credentials.
- No `agents` invocation.
- No repository CRUD for later GraphStore objects.
- No `sqlx::migrate!` or embedded migrations.

## Supported Surface

- Deployment mode: Rust library and contract tests.
- Customer cohort: later Phase 0B migration WUs and internal Rust harness tests.
- Adjacent public paths: WU-0A app state SQLite pool, WU-0A temp harness, Phase 0A scaffold command count, and contract fixtures.
- Blast radius: additive GraphStore module, contract DTO module, migration SQL file, fixtures, tests, and one bounded scaffold-contract assertion update.
- Migration path: fresh SQLite databases apply `0001_schema_versions.sql`; existing databases without `schema_versions` bootstrap it through the same runner.
- Rollback path: no destructive rollback is supported in WU-0B-01; remove the migration module and migration file before release if the design is rejected.
- Observability: contract tests inspect `schema_versions`, report vectors, exact error variants, enum round-trips, and absence of extra durable tables.

## Assumptions

- A1: Later Phase 0B WUs can add one file per migration under the same numeric convention. Evidence: Phase 0B roadmap assigns migration ownership per WU. Invalidated by a revised roadmap requiring an external migration registry.
- A2: A stable text timestamp is enough for the contract `Timestamp` field in Phase 0B. Evidence: existing DTO contracts use JSON-stable strings and this WU has no time arithmetic requirement. Invalidated by a contract requiring typed chrono values.
- A3: Rollback is deliberately unsupported in this WU. Evidence: acceptance criteria require the unsupported rollback error and history preservation, not reverse DDL. Invalidated by a revised WU requiring down migrations.
- A4: Hand-rolled migrations are acceptable because the ticket explicitly allows them. Evidence: ticket notes either `sqlx::migrate` or hand-rolled is fine if justified. Invalidated by a review requiring `sqlx` ownership.

## Test Intent

- Fresh ordered apply: verify a WU-0A temp SQLite database applies a fixture manifest with N ordered migrations and records exactly N rows with expected version, name, checksum, timing, actor, and rollback state. Risk: bootstrap or recording drift. Level: particular-integration. Fixture: `fresh-db-applies-n-manifest.json`. Assumptions: A1, A2.
- Idempotent rerun: run the same directory twice and assert the second report applies nothing and row snapshots are unchanged. Risk: migration history rewrite. Level: particular-integration. Fixture: same manifest. Assumption: A1.
- Checksum mismatch: mutate an applied file and assert exact `VersionChecksumMismatch` with unchanged rows. Risk: silent drift. Level: particular-integration. Fixture: `error-version-checksum-mismatch.json`. Assumption: A1.
- Duplicate/out-of-order rejection: assert duplicate fixture returns `OutOfOrderVersion` before applying later files, and applied-name conflict returns `VersionAlreadyAppliedDifferently`. Risk: ambiguous version history. Level: particular-integration. Fixtures: per-error fixtures. Assumption: A1.
- Unsupported rollback: call the rollback helper for an applied version and assert exact `RollbackUnsupported` with unchanged rows. Risk: destructive history changes. Level: particular-integration. Fixture: `error-rollback-unsupported.json`. Assumption: A3.
- Rollback state round-trip: serde and SQL row tests cover all four states and reject unknown states. Risk: enum drift or permissive decoding. Level: particular-integration. Fixture: `rollback-states.json`. Assumption: A2.
- Error taxonomy: every `MigrationError` variant has a named fixture and exact equality assertion. Risk: caller-visible error drift. Level: unit/particular-integration. Fixtures: `error-*.json`.
- Domain-table absence: after the WU-0B-01 migration directory runs, assert only `schema_versions` and SQLite internal tables exist. Risk: table ownership leakage. Level: particular-integration. Fixture: shipped `src-tauri/migrations`.
