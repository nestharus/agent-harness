# WU-0A-06 Proposal: IpcEvent Envelope Type

## Design

Add a narrow shared IPC event envelope for Phase 0A:

- Rust owns the serde DTO and error taxonomy in `src-tauri/src/contracts/ipc_event.rs`.
- Rust event construction lives in `src-tauri/src/events/ipc_event.rs`, using the existing `EventTopic` taxonomy from WU-0A-05.
- TypeScript mirrors the generic DTO, error union, and runtime shape parser in `src/contracts/ipc-event.ts`.
- Contract fixtures under `product-strategy/contracts/fixtures/wu-0a-06/` are the cross-language source of truth for canonical envelope shapes, builder inputs, error variants, and invalid parser shapes.

`IpcEvent<T>` is generic on payload in both Rust and TypeScript. The envelope does not inspect domain payload semantics; it only checks that the payload can serialize before Rust emits an event. The TypeScript parser receives a caller-supplied payload parser so payload validation remains explicit at the consuming contract boundary instead of being erased to `unknown`.

## Scope

- Preserve the documented `IpcEvent<T>` fields: `event_id`, `workspace_id`, `topic`, `payload`, `created_at`, and optional `trace_context_id`.
- Preserve the documented `IpcEventError` variants: `EmptyEventId`, `EmptyWorkspaceId`, `UnknownTopic`, and `PayloadSerializationFailed`.
- Add `build_ipc_event(workspace_id, topic, payload, trace_context_id)` with generated non-empty `event_id` and `created_at`.
- Add a raw-topic construction helper for fixture-level validation that maps invalid raw topics to `UnknownTopic` before event routing.
- Add shared Rust and TypeScript contract tests backed by durable JSON fixtures.

## Anti-Scope

- No IPC subscription command implementation.
- No event bus, channel, producer, or Tauri command registration.
- No domain payload schemas, GraphStore, provider, optimizer, worker, question, recovery, budget, or audit behavior.
- No trace context creation or validation beyond preserving the optional `trace_context_id` string.
- No durable event ID registry or timestamp persistence.

## Supported Surface

- Deployment mode: local Phase 0A Tauri scaffold and library contract tests.
- Customer cohort: internal contract consumers and future Phase 0A/0C IPC slices importing the Rust/TS DTOs.
- Public paths: Rust library consumers and TypeScript contract importers.
- Adjacent paths in blast radius: WU-0A-05 `EventTopic`, contract module declarations, event module declarations, and `bun run *` / Cargo checks.
- Migration path: additive contract, event module, fixtures, and tests.
- Rollback path: remove the added WU-0A-06 files and module declarations.
- Observability: Rust contract tests and Vitest tests expose envelope drift, builder behavior, raw-topic rejection, serialization failure mapping, and error taxonomy drift.

## Assumptions

- A1: Event IDs only need to be opaque non-empty strings in Phase 0A. Evidence: the WU contract requires `event_id: string` and acceptance criteria only require non-empty builder output. Invalidated by a revised WU requiring UUID format, monotonic ordering, or persistence.
- A2: `created_at` only needs to be an opaque non-empty timestamp string in Phase 0A. Evidence: the WU contract names `created_at: string` without a required timestamp format. Invalidated by a revised WU requiring RFC3339 or a specific clock source.
- A3: Payload semantics are outside this envelope WU. Evidence: `IpcEvent<T>` is generic and the ticket excludes GraphStore/provider/agents work. Invalidated by a revised WU adding concrete payload schemas to this slice.
- A4: `UnknownTopic` must be reachable at a raw input boundary even though `build_ipc_event` receives typed `EventTopic`. Evidence: acceptance criteria explicitly require invalid raw topic construction to return `UnknownTopic`. Invalidated by a revised WU removing raw-topic validation from this boundary.

## Test Intent

- Rust DTO shape and serde round-trip: verify canonical and minimal `IpcEvent<T>` fixture shapes preserve required fields, optional trace omission, topic serialization, and payload generics. Risk: Rust/TS contract drift. Level: particular-integration. Fixtures: `canonical-event.json`, `minimal-event.json`. Assumptions: A1, A2, A3.
- Rust build success behavior: verify builder output has non-empty generated `event_id` and `created_at`, preserves workspace/topic/payload/trace, and round-trips through serde. Risk: builder drops envelope metadata or payload. Level: unit. Fixture: `build-success.json`. Assumptions: A1, A2, A3.
- Rust error reachability and taxonomy: verify empty workspace, unknown raw topic, and non-serializable payload inputs reach documented errors, and every error variant round-trips with unknown variants rejected. Risk: unreachable or renamed error surface. Level: unit/particular-integration. Fixtures: `build-errors.json`, `ipc-event-errors.json`. Assumption: A4.
- TypeScript DTO and parser parity: verify TypeScript accepts fixture-shaped generic events, rejects unknown fields or bad topics, preserves optional `trace_context_id`, and keeps the error union aligned with Rust fixtures. Risk: TypeScript accepts values Rust rejects or erases payload shape. Level: unit/typecheck. Fixtures: `canonical-event.json`, `minimal-event.json`, `invalid-events.json`, `ipc-event-errors.json`, `build-errors.json`. Assumptions: A3, A4.
