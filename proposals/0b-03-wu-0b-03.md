# WU-0B-03 Proposal: GraphStore Repository Fixture Harness

## Design

Add a Rust-only GraphStore fixture builder that composes the existing Phase 0A temp harness, WU-0B-01 migration runner, and WU-0B-02 prelude. The supported public surface is:

```text
GraphStorePool { sqlite_url, sqlite, migrations_applied, workspace_root }
GraphStoreFixture { pool, workspace_id?, graph_version?, created_refs }
GraphStoreRepo<T> { insert, get, list_by_workspace }
create_graphstore_fixture(seed_plan) -> Result<GraphStoreFixture, GraphStoreError>
reset_graphstore_fixture(fixture) -> Result<(), GraphStoreError>
```

`GraphStorePool` wraps the live `sqlx::SqlitePool`, records the migration versions applied by `run_migrations`, stores the SQLite URL used by the fixture, and stores the temp workspace root from `temp_harness_state`. `GraphStoreFixture` carries that pool plus optional graph identifiers. For WU-0B-03 there are no Phase 0B domain rows yet, so `workspace_id`, `graph_version`, and `created_refs` are empty by default. `created_refs` is still present now so every future seed-created reference can be centrally validated through WU-0B-02 `OpaqueId<T>`.

`GraphStoreRepo<T>` is a trait contract only. There is no dynamic catch-all repository. Each downstream WU defines its typed repository implementation and decides which record type owns `insert`, `get`, and `list_by_workspace`.

## Seed Plan

`GraphStoreSeedPlan` is intentionally empty for accepted Phase 0B-03 behavior. The canonical valid seed is `{}`. The only non-empty seed input recognized by this WU is a future-WU reference request used to prove rejection behavior; any such request returns `GraphStoreError::UnknownRef` before the temp harness or migration runner is invoked.

Future WUs extend the seed-plan grammar by adding their own typed variants and seeding code. They must also add reset deletion clauses for their owned rows and must keep the `schema_versions` table untouched.

## Create

`create_graphstore_fixture(seed_plan)` first validates the seed plan. If it contains a future-WU reference, the function returns `UnknownRef` without creating a temp harness or applying migrations. For the empty plan, it calls `temp_harness_state("empty", None, None, vec![])`, resolves the harness app state, runs `run_migrations(pool, src-tauri/migrations)`, and returns a `GraphStoreFixture` whose `migrations_applied` is the migration report's `applied_versions`.

## Reset

`reset_graphstore_fixture(fixture)` deletes WU-owned rows and preserves migration history exactly. WU-0B-03 owns no domain tables, so reset is currently a no-op against data rows. It must not drop, truncate, rewrite, or update `schema_versions`.

## Anti-Scope

- No Tauri commands, invoke handlers, command registration, or UI panes.
- No migration files beyond `src-tauri/migrations/0001_schema_versions.sql`.
- No Phase 0B domain tables.
- No subprocess spawning, real `agents` invocation, provider probes, optimizer execution, or recovery execution.
- No repository implementation for a domain object that belongs to a future WU.

## Supported Surface

Deployment mode is Rust test/dev fixture only. The current user-reachable app surface remains the existing Phase 0A shell and `subscribe_workspace_events` command. The adjacent blast radius is limited to GraphStore test setup helpers and integration tests. Migration path is additive module wiring; rollback is deleting the new fixture module, contract artifact, and tests. Observability is the returned `GraphStoreFixture` shape plus direct SQLite assertions in contract tests.

## Assumptions

- A1: WU-0A-14a remains the single source for isolated temp SQLite handles. Evidence: `temp_harness_state` owns temp database creation. Invalidated by a future harness replacing the SQLite opening path.
- A2: WU-0B-01 migration history is represented only by `schema_versions`. Evidence: shipped migrations directory has only `0001_schema_versions.sql`. Invalidated by a later base migration adding more tables.
- A3: WU-0B-03 owns no domain rows. Evidence: ticket anti-scope forbids Phase 0B domain tables. Invalidated by a revised WU assigning a domain table to 0B-03.
- A4: Opaque IDs must not become paths or content hashes. Evidence: WU-0B-02 `OpaqueId<T>::new` contract. Invalidated only by a WU-0B-02 contract revision.

## Test Intent

- Empty fixture creation. Risk: fixture bypasses temp isolation or migration reporting. Level: particular-integration. Fixture source: `empty-seed-plan.json`. Signal: returned fixture has isolated temp path, `migrations_applied == [1]`, only `schema_versions`, no refs.
- Future-WU seed rejection. Risk: tests seed objects before their owning WU exists. Level: component. Fixture source: `unknown-ref-seed-plan.json`. Signal: `GraphStoreError::UnknownRef` and structural proof that validation precedes temp harness creation.
- Reset preservation. Risk: reset destroys migration history. Level: particular-integration. Fixture source: `reset-preserves-migration-history.json`. Signal: `schema_versions` rows are byte-for-byte equal before and after reset, and migrations rerun as skipped.
- Opaque-ID hook. Risk: future seeded refs bypass WU-0B-02 invariants. Level: unit/component. Fixture source: `graphstore-fixture-shape.json`. Signal: validation hook exists and accepts the empty created-ref set.
- Side-effect absence. Risk: fixture setup leaks subprocess, provider, UI, optimizer, recovery, command, or migration side effects. Level: component structural. Fixture source: `no-side-effects-assertions.json`. Signal: source grep rejects forbidden tokens and runtime table list stays at `schema_versions`.
- Independent fixtures. Risk: downstream tests share global database state. Level: particular-integration. Fixture source: `graphstore-pool-shape.json`. Signal: two fixtures in one test have different SQLite URLs/workspace roots and separate schema history.
