# WU-0A-15 Proposal: FakeAgentsFixture Subprocess Double

## Design

Add a Rust-only `install_fake_agents_fixture(handle, scenario_name)` builder in `src-tauri/src/test_harness/fake_agents.rs`. The builder resolves `scenario_name` through an internal scenario registry, loads that scenario manifest, installs a fake executable under the WU-0A-14a temp harness fixture root, materializes argv/transcript reference files, and returns a serializable `FakeAgentsFixture`.

The fixture root is resolved from the live `HarnessAppState` associated with `TempHarnessHandle`, then scoped under the handle's `fixture_manifest_id`. Fake executables use a derived path such as `<temp-harness fixture_root>/<fixture_manifest_id>/fake-agents-success`. The builder never executes the fake executable and never executes the real `/home/nes/.local/bin/agents` binary.

The scenario registry initially documents:

- `success`: argv recorded, configured stdout/stderr refs written, `exit_status: 0`, `child_acceptance_state: "accepted"`.
- `nonzero-exit`: argv recorded, stdin/stdout/stderr refs written, nonzero `exit_status` such as `42`.
- `cancellation`: argv recorded, no successful child acceptance simulated, `child_acceptance_state: "ambiguous"`.
- `timeout`: argv recorded, stderr transcript ref preserved for later Phase 0C ingestion tests, `child_acceptance_state: "timed_out"`.
- `unknown-state-fixture`: valid fixture whose `child_acceptance_state` is `"unknown"`.
- `rejected-fixture`: valid fixture whose `child_acceptance_state` is `"rejected"`.
- `unknown`: not present in the registry and reserved for `UnknownScenario` error tests.

## FakeAgentsFixture

`FakeAgentsFixture` has exactly these contract fields:

- `bin_path`
- `scenario_name`
- `argv_log_ref`
- `stdin_ref`
- `stdout_ref`
- `stderr_ref`
- `exit_status`
- `oulipoly_invocation`
- `parent_invocation_id`
- `session_id`
- `child_acceptance_state`

The optional refs and invocation/session fields serialize as absent when `None`.

## FakeAgentsFixtureError

The error taxonomy has exactly six variants:

- `UnknownScenario`: `scenario_name` is not present in the internal registry.
- `FixtureInstallFailed`: writing the fake executable or ref files under the temp harness fixture root fails, including fixture-configured write failure.
- `ArgvLogMissing`: the scenario manifest declares an argv-log ref, but that file is missing after install.
- `TranscriptRefMissing`: the scenario manifest declares stdout or stderr refs, but one of those files is missing after install.
- `RealAgentsPathRejected`: a scenario attempts to install at `/home/nes/.local/bin/agents`.
- `InvalidChildAcceptanceState`: fixture JSON contains a `child_acceptance_state` string outside `unknown`, `accepted`, `rejected`, `timed_out`, or `ambiguous`.

## Bin Path Safety

The fake executable is installed under the temp harness fixture root, scoped by `fixture_manifest_id`, for example:

```text
<fixture_root>/<fixture_manifest_id>/fake-agents-success
```

The installer rejects any requested path equal to `/home/nes/.local/bin/agents` before writing. For ordinary fake paths, it creates the fixture directory, writes the executable, canonicalizes the fixture root and executable path, then verifies the canonical executable is under the canonical fixture root and is not equal to the canonical real agents path when that path exists.

## Anti-Scope

- No new Tauri commands.
- No real `agents` binary execution.
- No fake binary execution; this WU installs fake binaries only.
- No GraphStore DDL or migrations.
- No provider config or credentials.
- No `src/**/*` TypeScript edits.

## Supported Surface

- Deployment mode: Rust library/test harness only.
- Customer cohort: internal Rust contract tests and future development scripts.
- Adjacent public paths: WU-0A-14a `TempHarnessHandle`, live harness app-state lookup, storage layout fixture root, and scaffold command count invariant.
- Blast radius: additive Rust contract/test-harness modules plus contract documentation and fixtures.
- Migration path: additive only; existing temp harness handles remain unchanged.
- Rollback path: remove this proposal, contract doc, fixtures, Rust DTO module, test harness module, module declarations, and contract test.
- Observability: contract tests verify serde round-trips, all child acceptance states, all documented scenarios, path safety, all error variants, and scaffold command invariants.

## Assumptions

- A1: The WU-0A-14a live harness registry is the correct source for the temp harness fixture root. Evidence: `HarnessAppState` stores `LocalStorageLayout`, including `fixture_root`. Invalidated by a future contract requiring `TempHarnessHandle` to carry fixture-root data directly.
- A2: Installing a fake executable is sufficient for Phase 0A and must not imply process execution. Evidence: the ticket explicitly forbids real or fake binary execution. Invalidated by a revised WU that requires spawn behavior in this phase.
- A3: Scenario manifests may drive test-only error paths. Evidence: the ticket requires fixture JSON for invalid child acceptance state and manifest-declared missing refs. Invalidated by a revised contract that removes manifest-backed scenarios.

## Test Intent

- DTO serde round-trip: verify all 11 `FakeAgentsFixture` fields preserve stable names, optional fields can be present or absent, and unknown fields are rejected. Risk: Rust contract drift. Level: particular-integration. Fixtures: `fixture-round-trip.json`. Assumption: A3.
- Child acceptance states: verify every valid state round-trips and is reachable through a documented scenario. Risk: unreachable state modeling. Level: particular-integration. Fixtures: scenario manifests. Assumption: A3.
- Bin path safety: verify `success` installs under the temp harness fixture root and not `/home/nes/.local/bin/agents`, using canonical path comparison. Risk: accidental real binary use. Level: particular-integration. Fixtures: `bin-path-canonicalization.json`, `real-agents-path-rejected.json`. Assumption: A1.
- Scenario behavior: verify `success`, `nonzero-exit`, `cancellation`, and `timeout` materialize the documented refs, exit statuses, and child acceptance states without executing a subprocess. Risk: fake fixture drift. Level: particular-integration. Fixtures: scenario manifests. Assumption: A2.
- Error taxonomy: verify all six `FakeAgentsFixtureError` variants serialize and are reachable through documented fixtures or scenario names. Risk: caller-visible error drift or unreachable failures. Level: unit/particular-integration. Fixtures: per-error fixtures. Assumption: A3.
- Scaffold invariant: verify `phase_0a_scaffold_commands()` remains a single `subscribe_workspace_events` command. Risk: command leakage. Level: particular-integration.
