# WU-0B-06 Proposal: GraphWorkspace

## Scope

WU-0B-06 adds the inert root local container for Phase 0B graph state:

```text
GraphWorkspace {
  workspace_id: OpaqueId<GraphWorkspace>,
  schema_version: i64,
  active_orchestrator_id: OpaqueId<Orchestrator>,
  current_graph_version: i64,
  storage_root: String,
  policy_set_id: OpaqueId<PolicySet>,
  active_configuration_id: OpaqueId<GraphConfiguration>,
  is_active_default: bool,
  meta: RecordMeta
}
```

`schema_version` is the applied schema version from `schema_versions(version)`. It is an integer FK, not a workspace-local profile string, because Phase 0B already has durable schema version history and the workspace row should identify the migration contract it was created under.

`current_graph_version` starts at `0`, representing an empty graph before later node/edge WUs append graph content.

`active_orchestrator_id` is an opaque reference string only. The orchestrator table ships in a later Phase 0B WU, so this WU deliberately adds no FK for it.

## Schema

`src-tauri/migrations/0b/06_graphworkspace.sql` creates exactly one durable table, `graph_workspaces`.

Columns:

- `workspace_id_value TEXT NOT NULL`
- `workspace_id_namespace TEXT NOT NULL`
- `schema_version INTEGER NOT NULL`
- `active_orchestrator_id_value TEXT NOT NULL`
- `active_orchestrator_id_namespace TEXT NOT NULL`
- `current_graph_version INTEGER NOT NULL`
- `storage_root TEXT NOT NULL`
- `policy_set_id_value TEXT NOT NULL`
- `policy_set_id_namespace TEXT NOT NULL`
- `active_configuration_id_value TEXT NOT NULL`
- `active_configuration_id_namespace TEXT NOT NULL`
- `is_active_default INTEGER NOT NULL CHECK (is_active_default IN (0, 1))`
- RecordMeta: `created_at`, `updated_at`, `actor`, `record_policy_version`

Constraints and indexes:

- `UNIQUE(workspace_id_value, workspace_id_namespace)`
- FK `schema_version -> schema_versions(version)`
- FK `(policy_set_id_value, policy_set_id_namespace) -> policy_sets(policy_set_id_value, policy_set_id_namespace)`
- FK `(active_configuration_id_value, active_configuration_id_namespace) -> graph_configurations(configuration_id_value, configuration_id_namespace)`
- index `idx_graph_workspaces_workspace_id`
- index `idx_graph_workspaces_policy_set_id`
- index `idx_graph_workspaces_active_configuration_id`
- partial unique index `idx_graph_workspaces_one_active_default ON graph_workspaces(is_active_default) WHERE is_active_default = 1`

## Repository

`GraphWorkspaceRepo` owns:

- `new(pool: SqlitePool)`
- `insert_graph_workspace(record) -> Result<GraphWorkspace, GraphStoreError>`
- `get_graph_workspace(id) -> Result<Option<GraphWorkspace>, GraphStoreError>`
- `list_graph_workspaces_by_namespace(workspace_namespace) -> Result<Vec<GraphWorkspace>, GraphStoreError>`
- `set_active_configuration(workspace_id, configuration_id) -> Result<GraphWorkspace, GraphStoreError>`
- `advance_graph_version(workspace_id, expected_version) -> Result<GraphWorkspace, GraphStoreError>`

`insert_graph_workspace` validates every opaque ID, validates RecordMeta, requires `schema_version > 0`, `current_graph_version >= 0`, and non-empty `storage_root`, then inserts inside an explicit transaction. Duplicate workspace IDs return `DuplicateId`; missing FK targets return `UnknownRef`.

`set_active_configuration` validates both opaque IDs, verifies `configuration_id` exists, updates only `active_configuration_id` and `RecordMeta.updated_at`, and returns `UnknownRef` for an unknown workspace or configuration. It does not mutate policy, schema version, storage root, orchestrator, graph version, actor, or record policy version.

`advance_graph_version` validates the workspace ID and `expected_version >= 0`, selects the current row in a transaction, compares `current_graph_version` to `expected_version`, and updates `current_graph_version + 1` plus `RecordMeta.updated_at` only on a match. A mismatch returns `GraphStoreError::OptimisticConflict` without changing the row.

## Invariants

Most workspace fields are append-only by convention. Because `workspace_id` is unique and this table is the root local container, the only permitted updates are:

- `set_active_configuration`: `active_configuration_id` and `updated_at`
- `advance_graph_version`: `current_graph_version` and `updated_at`

`policy_set_id`, `schema_version`, `storage_root`, and `active_orchestrator_id` cannot be modified after insert.

At most one row may have `is_active_default = 1`. The repository checks this before insert and the partial unique index enforces it at the database layer.

## Anti-Scope

This WU adds no graph nodes or edges, no Tauri commands, no UI panes, no subprocess launch, no provider probe, no optimizer execution, and no recovery execution.

## Test Intent

- Schema creation: verify declared columns, FKs, unique constraints, indexes, partial unique active-default index, JSON actor check, and RecordMeta fields.
- Round-trip: insert/get must preserve every scalar, bool, opaque ID, timestamp, and RecordMeta field byte-equivalent.
- Transaction rollback: FK violation leaves `graph_workspaces` row count unchanged.
- No side effects: command count remains one and runtime durable tables are only `schema_versions`, `policy_sets`, `graph_configurations`, and `graph_workspaces`.
- Boundary: contract tests import only WU-owned contract and predecessor contract surfaces.
- Active default: one default row inserts; a second default row returns `InvariantViolation` with no partial write.
- Active configuration mutation: valid call changes only `active_configuration_id` and `updated_at`; missing configuration returns `UnknownRef` with no row change.
- Graph version OCC: valid expected version increments once; stale expected version returns `OptimisticConflict` with no row change.
