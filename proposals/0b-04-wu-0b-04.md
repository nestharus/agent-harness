# WU-0B-04 Proposal: PolicySet Durable Governance Bundle

## Design

Add `PolicySet` as the first Phase 0B durable domain table. The Rust surface is inert repository code only:

```text
PolicySet {
  policy_set_id: OpaqueId<PolicySet>,
  summary_contract_version: JsonField<PolicyVersionRef>,
  render_policy_version: JsonField<PolicyVersionRef>,
  identity_policy_version: JsonField<PolicyVersionRef>,
  privilege_policy_version: JsonField<PolicyVersionRef>,
  tool_protocol_policy_version: JsonField<PolicyVersionRef>,
  budget_policy_version: JsonField<PolicyVersionRef>,
  review_sampling_policy_version: JsonField<PolicyVersionRef>,
  recovery_policy_version: JsonField<PolicyVersionRef>,
  configuration_policy_version: JsonField<PolicyVersionRef>,
  provider_policy_version: JsonField<PolicyVersionRef>,
  meta: RecordMeta
}

PolicyVersionRef {
  policy: String,
  version: String,
  previous_version: Option<String>,
  payload: serde_json::Value
}
```

Each policy-version field is stored as a JSON `TEXT` column and decoded through the WU-0B-02 `JsonField<T>` codec. `payload` is inert metadata for downstream policy engines; WU-0B-04 never interprets it or enables a gate.

## policy_sets Table

`policy_sets` columns:

- `row_id INTEGER PRIMARY KEY`
- `policy_set_id_value TEXT NOT NULL`
- `policy_set_id_namespace TEXT NOT NULL`
- ten `*_policy_version TEXT NOT NULL CHECK (json_valid(...))` JSON columns
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`
- `actor TEXT NOT NULL CHECK (json_valid(actor))`
- `record_policy_version TEXT NOT NULL`
- `schema_version INTEGER NOT NULL DEFAULT 4 REFERENCES schema_versions(version)`
- `UNIQUE(policy_set_id_value, policy_set_id_namespace)`

Indexes:

- unique autoindex from `UNIQUE(policy_set_id_value, policy_set_id_namespace)`
- explicit lookup index on `(policy_set_id_value, policy_set_id_namespace)`
- namespace list index on `policy_set_id_namespace`

Rows are append-only at the repository boundary. There is no `UPDATE` method or upsert path. A governance change creates a new `PolicySet` row with a new `policy_set_id`; existing rows remain addressable for snapshots and audit events.

## Validation

Before insert, `insert_policy_set` validates the opaque ID, every policy-version envelope, and embedded `RecordMeta`. Failures return `GraphStoreError::InvariantViolation` except duplicate IDs, which return `DuplicateId`.

Per-field rules:

- empty: `policy` or `version` is empty or whitespace-only
- unknown: `policy` does not match the owning field token: `summary_contract`, `render`, `identity`, `privilege`, `tool_protocol`, `budget`, `review_sampling`, `recovery`, `configuration`, or `provider`
- malformed: `version` or `previous_version` is not `vMAJOR.MINOR.PATCH` with non-negative integer components
- non-monotonic: when `previous_version` is present, parsed `version` must be greater than parsed `previous_version`

`RecordMeta` uses WU-0B-02 `validate_record_meta`. The record policy version is metadata about this row, not a PolicyEngine enablement switch.

## Repository

`PolicySetRepo` wraps a `SqlitePool` and implements `GraphStoreRepo<PolicySet>`.

Methods:

- `insert_policy_set(record) -> Result<PolicySet, GraphStoreError>`
- `get_policy_set(policy_set_id) -> Result<Option<PolicySet>, GraphStoreError>`
- `list_policy_sets_by_workspace(workspace_id) -> Result<Vec<PolicySet>, GraphStoreError>`
- trait aliases through `insert`, `get`, and `list_by_workspace`

`list_by_workspace` treats `policy_set_id.namespace` as the current global/workspace namespace until `GraphWorkspace` exists. No `graph_workspaces` table is created in this WU.

## Transactions

`insert_policy_set` opens `pool.begin()` before validation and commits only after the insert succeeds. Any validation, duplicate, FK, enum, routing, or state-transition failure rolls back the transaction and leaves the row count unchanged.

## Migration Directory Decision

This WU uses option 1 and places the migration at `src-tauri/migrations/0b/04_policyset.sql`. The WU-0B-01 runner receives a bounded recursive directory walk that collects `*.sql` files below the supplied migration root, sorts by parsed version, and preserves version uniqueness across the whole tree. Scaffold assertions that previously hard-coded a flat directory are updated to allow the `0b` subdirectory and the shipped policy-set migration. WU-0B-01 shipped-table assertions are updated because WU-0B-04 intentionally introduces `policy_sets`.

## Anti-Scope

- No PolicyEngine value-slice gates.
- No UI panes, frontend behavior, or operator-visible affordance.
- No Tauri commands or command registration.
- No agent launch, provider probe, optimizer execution, reviewer sampling, or recovery execution.
- No other Phase 0B domain table.

## Supported Surface

Deployment mode is Rust GraphStore test/dev code and additive SQLite migration only. Customer cohort remains local single-user harness development. Public/user-reachable paths remain the Phase 0A shell and `subscribe_workspace_events`; this WU adds no new operator action. Adjacent blast radius is bounded to migration discovery, GraphStore fixture runtime tables, and new PolicySet repository tests. Migration path is additive through migration version 4 in the `0b` subdirectory. Rollback is not supported by the migration framework; code rollback means removing the new module and migration before it ships into a persistent environment. Observability is direct contract-test inspection of schema, rows, errors, and inert command surface.

Net value: this reduces the current Phase 0B risk that downstream snapshots and audit events will need policy references before a durable policy bundle exists. The blast radius is acceptable because behavior remains inert and the only framework patch is recursive migration discovery.

## Assumptions

- A1: It is acceptable for WU-0B-04 to satisfy the ticket's FK requirement by referencing `schema_versions(version)`, because no owning `GraphWorkspace` table exists yet and the ticket forbids additional domain tables. Evidence: WU-0B-04 is the first durable domain table. Invalidated by a revised ticket requiring `graph_workspaces`.
- A2: `policy_set_id.namespace` is the only available workspace/global partition until `GraphWorkspace` exists. Evidence: WU-0B-03 fixture exposes `workspace_id: None` and the WU allows `list_by_workspace` to be a global no-op. Invalidated by an earlier workspace-table WU being inserted before this ticket.
- A3: JSON policy-version envelopes are the narrowest way to satisfy JSON-column acceptance without adding uninterpreted policy-engine tables. Evidence: WU-0B-02 already provides `JsonField<T>`. Invalidated by a contract requiring scalar string columns only.
- A4: Append-only can be enforced at the repository boundary for this WU. Evidence: no update method is requested. Invalidated by a requirement for SQLite triggers preventing manual SQL updates.

## Test Intent

- Schema creation. Risk: first durable domain table misses columns, JSON checks, FK, unique, or indexes. Level: particular-integration. Fixture source: `canonical-row.json`. Signal: `sqlite_master` and PRAGMA introspection expose `policy_sets`, declared columns, FK to `schema_versions`, unique constraint, and indexes.
- Round-trip. Risk: repository loses or rewrites scalar, JSON, opaque-ID, timestamp, or metadata fields. Level: particular-integration. Fixture source: `round-trip.json`. Signal: `insert_policy_set` then `get_policy_set` returns byte-equivalent serialized fields.
- Transaction rollback. Risk: invalid inserts leave partial durable rows. Level: particular-integration. Fixture source: `rejection-matrix.json`. Signal: row count before and after invalid insert is unchanged.
- Side-effect absence. Risk: governance storage enables operator-visible behavior. Level: component structural. Fixture source: `no-side-effects.json`. Signal: command allowlist is unchanged and source/runtime assertions show no UI, agents, provider, optimizer, or recovery path.
- Contract boundary. Risk: tests inspect future services outside the WU. Level: component. Fixture source: this contract. Signal: WU-0B-04 tests use only migrations, fixture builder, prelude, and policyset repo.
- Rejection matrix. Risk: one policy-version field accepts empty, unknown, non-monotonic, or malformed versions. Level: unit/particular-integration. Fixture source: `rejection-matrix.json`. Signal: every field and every rejection mode returns `InvariantViolation`.
- Append-only governance. Risk: policy updates overwrite historical rows. Level: particular-integration. Fixture source: `append-only-governance.json`. Signal: inserting a later policy set creates a second row and both IDs remain addressable.
