# WU-0A-08 Proposal: SubscribeWorkspaceEvents IPC Command

## Design

Register the first real Phase 0A Tauri command:

```text
subscribe_workspace_events(workspace_id, topic, channel)
  -> Result<subscription_id, SubscribeWorkspaceEventsError>
```

The command is scaffold scope, not value-slice scope. It validates `workspace_id`, parses the raw `topic` string through the WU-0A-05 `EventTopic` taxonomy, requires an available Tauri channel, then registers a workspace/topic subscription on the WU-0A-04 event bus. Registration creates a `Subscription` model with `subscription_id`, `workspace_id`, `topic`, and the Tauri `Channel<IpcEvent<Value>>` handle. The event-bus handle owns the active subscription so the broadcast receiver and channel handle remain alive after the command returns.

## Channel Mechanism

The runtime streaming mechanism is Tauri v2 `Channel<IpcEvent<Value>>`. Tests use a recording channel fixture built with `Channel::new` so the test can inspect what would have been sent without a frontend webview. This WU does not emit domain payloads from the command itself. WU-0A-10 may later produce backend span events on the `runtime` topic; this WU only creates the channel-backed subscription path.

## Subscription ID

`subscription_id` is a real non-empty unique id using the existing WU-0A-06 style prefix pattern, for example `sub-{nanos}-{counter}`. The id is returned to IPC callers and is also the lookup key for the event-bus subscription metadata in tests.

## Error Taxonomy

`SubscribeWorkspaceEventsError` has exactly these variants:

- `EmptyWorkspaceId`: `workspace_id.trim().is_empty()`.
- `UnknownTopic`: `topic` is not one of the documented WU-0A-05 lowercase topic strings.
- `ChannelUnavailable`: the channel argument is absent or the test seam marks it unavailable.
- `AppStateUnavailable`: Tauri managed `HarnessAppState` is missing; runtime command extraction normally supplies state, and the direct test seam verifies this path.

## Scaffold Command Invariant

WU-0A-08 changes the scaffold invariant from “Phase 0A registers zero commands” to “Phase 0A registers only the allowed scaffold command list.” Add an internal `phase_0a_scaffold_commands()` list containing exactly `["subscribe_workspace_events"]`; make `registered_command_count()` return that list length. Existing scaffold tests should assert the registered set equals the scaffold list and still reject unknown value-slice command registrations.

## Inert Non-Runtime Topics

All documented `EventTopic` variants can be subscribed to. For non-runtime topics, the subscription is registered against the bus but no Phase 0A producer fires, so the recording channel observes zero domain payloads in the documented test window.

## Anti-Scope

No GraphStore queries, GraphStore tables, migrations, provider credentials, `agents` invocation, optimizer cycles, graph mutation event producers, or runtime backend-span producers are added here.

## Supported Surface

- Deployment mode: local Tauri app bootstrap.
- Customer cohort: internal Phase 0A harness users and contract tests.
- User-reachable path: frontend IPC command name `subscribe_workspace_events`.
- Adjacent paths: WU-0A-04 app state/event bus, WU-0A-05 topics, WU-0A-06 IPC event envelope, WU-0A-07 command taxonomy, scaffold contract tests.
- Migration path: replace the old zero-command assertion with the scaffold command allowlist.
- Rollback path: remove the command handler and restore the empty scaffold list.
- Observability: command count and subscription metadata are test-visible; no production telemetry is introduced.

## Assumptions

- A1: The WU-0A-04 event bus is the correct owner for active subscriptions. Evidence: it already owns a broadcast sender for `IpcEvent<Value>`. Invalidated by a revised state architecture.
- A2: `subscribe_workspace_events` is scaffold scope. Evidence: ticket explicitly calls this the first real Phase 0A command and says to distinguish scaffold commands from value-slice commands. Invalidated by a revised command-registration policy.
- A3: The command must parse raw topic strings to reach `UnknownTopic`. Evidence: acceptance criteria require an unknown topic string error. Invalidated by a revised IPC schema that rejects unknown topics before command execution.
- A4: Non-runtime topics are inert in Phase 0A. Evidence: WU-0A-05 marks only `runtime` live and this ticket forbids domain producers. Invalidated by a revised Phase 0A producer WU.

## Test Intent

- Rust command registration and scaffold invariant: verify registered command count/list is exactly `subscribe_workspace_events` and no value-slice command names are present. Risk: accidental command leakage. Level: particular-integration. Fixtures: scaffold allowlist.
- Rust every-topic happy path: verify each documented `EventTopic` succeeds and registers metadata under workspace/topic. Risk: topic coverage drift. Level: particular-integration. Fixtures: `event-topic-happy-paths.json`. Assumptions: A1, A3.
- Rust subscription id semantics: verify non-empty unique ids and event-bus association. Risk: unusable or untracked subscriptions. Level: particular-integration. Fixtures: `subscription-id-shape.json`. Assumption: A1.
- Rust error taxonomy: verify `EmptyWorkspaceId`, `UnknownTopic`, `ChannelUnavailable`, and `AppStateUnavailable`. Risk: caller-visible error drift. Level: unit/particular-integration. Fixtures: per-error JSON files. Assumption: A3.
- Rust inert non-runtime topic: verify a non-runtime subscription succeeds and the recording channel receives zero domain payloads in the fixture window. Risk: Phase 0A accidentally starts value-slice event flow. Level: particular-integration. Fixtures: `inert-non-runtime-topic.json`. Assumption: A4.
- TypeScript DTO/parser: verify canonical args/response/error fixtures round-trip and malformed shapes are rejected. Risk: Rust/TS contract drift. Level: unit/typecheck. Fixtures: WU-0A-08 fixture directory.
