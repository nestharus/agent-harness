# Proposal: WU-0B-16 BudgetLedger

Implement `BudgetLedger` as an inert Phase 0B GraphStore record. The row has the declared 14 contract fields plus `RecordMeta`; `provider_state_id` is a soft reference until WU-0B-17, and `cache_prefix_hash` is optional.

## Schema

Create one durable table, `budget_ledgers`, with:

- Opaque ID columns for `budget_ledger_id`, `workspace_id`, `scope_id`, and optional `provider_state_id`.
- FK from `workspace_id` to `graph_workspaces` and FK from `schema_version` to `schema_versions`.
- `UNIQUE(budget_ledger_id_value, budget_ledger_id_namespace)`.
- Indexes on `workspace_id`, `scope_type`, and `budget_state`.
- SQL `CHECK` constraints for all enum values, optional provider-state ID column pairing, non-negative counters, and the policy-action matrix.

## Policy-Action Matrix

| budget_state | allowed policy_action values |
| --- | --- |
| `within` | `none`, `warn` |
| `near_limit` | `warn`, `narrow_scope` |
| `exceeded` | `require_user_approval`, `block`, `narrow_scope` |
| `blocked` | `block` |

## Repository

Add `BudgetLedgerRepo` with insert/get/list-by-workspace methods. Inserts validate opaque IDs, `RecordMeta`, non-negative counters, and the policy-action matrix before writing inside an explicit transaction.

## Tests

Add contract tests and fixtures for schema creation, round-trip, rollback, side-effect absence, WU boundary, enum variants and unknown rejection, counter validation, and the policy-action matrix.
