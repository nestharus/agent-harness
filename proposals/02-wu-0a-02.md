# WU-0A-02 Proposal: HarnessSettings DTO and Settings Loader

## Design

Add a narrow Phase 0A settings contract shared by Rust and TypeScript:

- Rust owns `HarnessSettings`, `HarnessLogLevel`, and `SettingsError` in `src-tauri/src/contracts/harness_settings.rs`.
- TypeScript mirrors the same DTO and string unions in `src/contracts/harness-settings.ts`.
- `load_harness_settings(cwd, env_overrides, config_file)` lives in `src-tauri/src/settings.rs` and merges an optional JSON config file with explicit env override keys.

The loader treats settings as literal strings except for `agent_runner_bin`, which must resolve to an existing file relative to `cwd` when it is not absolute. `storage_root` and `database_path` are not canonicalized in this WU because path containment belongs to WU-0A-03.

## Scope

- Preserve the documented settings fields: `workspace_id`, `storage_root`, `database_path`, `agent_runner_bin`, `log_level`, and optional `profile_name`.
- Preserve the exact log-level union: `trace`, `debug`, `info`, `warn`, `error`.
- Preserve the documented `SettingsError` variants and make every variant reachable through fixture-backed tests.
- Document and fixture the config and env merge contract.

## Anti-Scope

- No GraphStore schema, migrations, seeded data, provider config, subprocess supervision, IPC command registration, app-state container, or storage-layout derivation.
- No default discovery of real user environment variables. Tests pass an explicit `env_overrides` map.
- No shell UI behavior changes beyond adding TypeScript contract code.

## Supported Surface

- Deployment mode: local Phase 0A desktop scaffold.
- Customer cohort: developer/test harness consumers only.
- Public paths: Rust library consumers and TypeScript contract importers.
- Adjacent paths: existing inert Tauri bootstrap and React shell remain command-free and provider-free.
- Migration path: additive files and module wiring only.
- Rollback path: remove the added contract/settings files and module declarations.
- Observability: contract tests expose loader success and every documented error variant.

## Assumptions

- A1: WU-0A-01 scaffold is present. Evidence: `src-tauri/src/lib.rs`, `package.json`, and existing WU-0A-01 contract tests. Invalidated by missing Rust/TS test roots or broken `bun run` scripts.
- A2: The settings loader should not validate storage containment. Evidence: WU-0A-03 owns `LocalStorageLayout` and path escape errors. Invalidated by a revised WU-0A-02 contract adding storage containment errors.
- A3: Explicit env override maps are enough for Phase 0A. Evidence: function signature takes `env_overrides` rather than reading process env directly. Invalidated by a revised contract requiring ambient environment reads.

## Test Intent

- Rust DTO shape and serde round-trip: verify canonical fixture field set and log-level serialization. Risk: Rust/TS contract drift. Level: particular-integration. Fixture: `canonical-settings.json`.
- Rust loader success: verify config plus env override merge returns expected settings. Risk: merge behavior ambiguity. Level: unit/particular-integration. Fixtures: `config-input.json`, `env-overrides.json`, `env-overridden-settings.json`.
- Rust error reachability: verify all documented `SettingsError` variants are emitted by fixture inputs. Risk: unreachable or renamed error surface. Level: unit. Fixtures: `error-*.json`.
- TypeScript DTO and parser shape: verify canonical JSON parses to the DTO and rejects extra/missing/invalid fields. Risk: TypeScript accepts shapes Rust does not own. Level: unit. Fixture: `canonical-settings.json`.
- TypeScript log-level type surface: compile-time checks for the exact log-level union. Risk: widened log-level type. Level: unit/typecheck. Source: documented union.
