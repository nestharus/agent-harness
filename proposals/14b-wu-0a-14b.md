# WU-0A-14b Proposal: Render With Harness React Testing Utility

## Design

`renderWithHarness(ui, seedName)` is a thin React Testing Library wrapper for frontend tests. It resolves `seedName` through fixture-owned WU-0A-14a temp harness metadata, parses the selected `TempHarnessHandle` with a TypeScript DTO that mirrors the Rust handle, seeds the WU-0A-07 `invokeCommand` fixture seam with command responses for that seed, and renders the supplied UI under fresh TanStack Query and TanStack Router context providers.

The helper returns the standard React Testing Library `RenderResult`: `container`, `baseElement`, `debug`, `rerender`, `unmount`, `asFragment`, and the normal `getBy*`, `queryBy*`, and `findBy*` query methods. It does not extend the public return shape with harness-specific fields.

The test router is memory-history based and uses TanStack Router's `RouterContextProvider` as the matching test wrapper for arbitrary React Testing Library UI. A fresh `QueryClient` and fresh router are created per call. The seeded IPC fixture registry is reset per call and cleared when the returned result is unmounted.

## Seed Failure Surfacing

Documented WU-0A-14a seed failures throw before React Testing Library mounts anything. Unknown seed names throw `TempHarnessErrorFailure` with `kind: "UnknownSeed"`. The documented `missing-manifest` seed throws `TempHarnessErrorFailure` with `kind: "FixtureManifestMissing"`. The helper never returns a partial `RenderResult` for a failed seed.

## TypeScript TempHarness DTO

`src/contracts/temp-harness.ts` mirrors the Rust `TempHarnessHandle` shape exactly:

- `workspace_id: string`
- `database_path: string`
- `fixture_manifest_id: string`
- `app_state_ready: boolean`

The parser rejects unknown fields, missing fields, and wrong primitive types. It also exposes the documented `TempHarnessError` discriminated union mirrored from WU-0A-14a.

## No Real Runtime Work

All IPC responses are seeded through the WU-0A-07 `invokeCommand` shim. `renderWithHarness` does not call Tauri invoke, spawn `/home/nes/.local/bin/agents`, apply GraphStore migrations, read provider credentials, or start any subprocess.

## Anti-Scope

- No new Tauri commands.
- No Rust file changes.
- No graph, provider, migration, credential, or process-spawn code.
- No changes to the Phase 0A command registration count.

## Supported Surface

Deployment mode: frontend Vitest/jsdom tests only.

Customer cohort: contributors writing React Testing Library tests for Phase 0A frontend UI.

Adjacent supported paths: `AppShell` still owns the production QueryClient/router wiring; WU-0A-07 still owns command parsing and response validation; WU-0A-14a still owns Rust temp harness state.

Migration path: tests can import `renderWithHarness` from `src/test/render-with-harness`.

Rollback path: remove the utility, contract DTO, and 14b fixtures; no persisted state or Rust runtime changes are involved.

Observability: Vitest assertions observe provider reachability, seeded IPC responses, no Tauri invoke fallback, and no mounted result on failed seeds.

## Assumptions

A1. WU-0A-14a fixtures remain the source of truth for seed names and temp harness errors. Evidence: `product-strategy/contracts/wu-0a-14a-temp-sqlite-harness-entrypoint.md`. Invalidated by renaming or removing those fixtures.

A2. Components under test import the default `invokeCommand` helper when they need app IPC. Evidence: WU-0A-07 helper in `src/ipc/invoke-command.ts`. Invalidated by a second IPC helper becoming supported.

A3. The harness renderer only needs a memory root route that renders the supplied UI, not production route matching. Evidence: WU-0A-14b ticket describes mounting supplied UI under router providers. Invalidated by tests needing app route modules.

## Test Intent

- DTO fixture parity: unit/component fixture test parses WU-0A-14a handle JSON and rejects invalid shapes. Risk: TypeScript accepts handles Rust would reject. Observable signal: parser returns the exact fixture object.
- RenderResult shape: component test calls `renderWithHarness` and checks documented keys. Risk: wrapper hides or mutates RTL return contract. Observable signal: functions and elements exist.
- Provider mounting: component test renders a probe using `useQueryClient` and `useRouter`. Risk: UI is not actually below QueryClient and TanStack Router context providers. Observable signal: probe marker renders.
- IPC seeding: component test calls `invokeCommand("ping_runtime", {})`. Risk: harness falls through to real Tauri invoke or returns undocumented data. Observable signal: documented response renders and mocked Tauri invoke is not called.
- Runtime side-effect absence: component test verifies no real agents path or migration command reaches Tauri. Risk: renderer escapes fixture seam. Observable signal: Tauri invoke spy has no calls.
- Seed failure: component test calls an unknown seed and expects `TempHarnessErrorFailure`. Risk: seed failure returns a mounted partial result. Observable signal: throw occurs and no test UI exists.
