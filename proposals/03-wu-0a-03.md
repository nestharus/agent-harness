# WU-0A-03 Proposal: LocalStorageLayout DTO

## Design

Add a narrow storage-layout contract shared by Rust and TypeScript:

- Rust owns `LocalStorageLayout` and `StorageLayoutError` in `src-tauri/src/contracts/local_storage_layout.rs`.
- TypeScript mirrors the DTO and error string union in `src/contracts/local-storage-layout.ts`.
- `derive_local_storage_layout(settings)` lives in `src-tauri/src/storage.rs` and derives evidence, fixture, log, and temp roots under `settings.storage_root`.
- The derivation keeps path checks lexical. Phase 0A has no durable app-state root, database opener, symlink policy, or filesystem canonicalization contract yet.

## Scope

- Preserve the documented layout fields: `storage_root`, `database_path`, `evidence_root`, `fixture_root`, `log_root`, and `temp_root`.
- Preserve `settings.database_path` when it is inside `settings.storage_root`.
- Derive distinct `evidence`, `fixtures`, `logs`, and `tmp` child roots under the storage root.
- Reject storage roots that lexically escape the workspace fixture boundary.
- Reject database and configured layout roots outside the storage root with the documented `StorageLayoutError` variants.

## Anti-Scope

- No GraphStore schema, migrations, provider configuration, app-state construction, SQLite opening, subprocess supervision, IPC command registration, or real filesystem directory creation.
- No symlink resolution or filesystem canonicalization.
- No ambient process environment reads.

## Supported Surface

- Deployment mode: local Phase 0A desktop scaffold.
- Customer cohort: developer/test harness consumers only.
- Public paths: Rust library consumers and TypeScript contract importers.
- Adjacent paths: WU-0A-02 settings loading remains string-preserving; existing event, trace, pane, shell, and Tauri command-free paths remain unchanged.
- Migration path: additive contract, storage module, fixtures, and tests.
- Rollback path: remove the added contract/storage files, fixtures, tests, and module declarations.
- Observability: contract tests expose layout derivation, every documented error variant, and strict TypeScript parsing.

## Assumptions

- A1: `HarnessSettings` is already available and intentionally does not validate storage containment. Evidence: WU-0A-02 proposal and contract. Invalidated by a revised settings contract that adds storage containment errors.
- A2: Phase 0A path containment is lexical. Evidence: WU-0A-03 only receives `HarnessSettings` strings and has no app-state or filesystem root input. Invalidated by a revised WU contract requiring canonical filesystem paths or symlink checks.
- A3: Derived roots use stable child names under `storage_root`. Evidence: WU-0A-03 acceptance criteria names derived evidence, fixture, log, and temp roots but does not specify operator configuration for those roots. Invalidated by a revised contract adding child-root settings fields.

## Test Intent

- Rust DTO shape and serde round-trip: verify canonical fixture field set and string values. Risk: Rust/TS contract drift. Level: particular-integration. Fixture: `canonical-layout.json`. Assumption: A1.
- Rust derivation success: verify layout derivation preserves an in-root database path and produces four distinct child roots under storage. Risk: broken path derivation. Level: unit. Fixture: `derive-success.json`. Assumption: A2 and A3.
- Rust error reachability: verify storage-root escape and database outside-storage inputs return documented variants, and configured invalid layout roots reach the child-root error variants. Risk: unreachable or renamed error surface. Level: unit. Fixtures: `derive-errors.json`, `invalid-layouts.json`. Assumption: A2.
- Rust error serde: verify all `StorageLayoutError` variants round-trip and unknown variants reject. Risk: Rust/TS error taxonomy drift. Level: particular-integration. Fixtures: `storage-layout-errors.json`, `invalid-storage-layout-error.json`.
- TypeScript DTO and parser shape: verify canonical JSON parses to the DTO and rejects extra or invalid fields. Risk: TypeScript accepts shapes Rust does not own. Level: unit/typecheck. Fixture: `canonical-layout.json`.
- TypeScript error union: compile-time and runtime checks for the exact error union. Risk: widened TypeScript error type. Level: unit/typecheck. Fixtures: `storage-layout-errors.json`, `derive-errors.json`.
