# WU-0A-06 — Shortcut Risk Review

**Gate:** Phase 4 shortcut.
**Severity:** LOW.

## Question

Do the chosen shortcuts compromise WU-0A-06's purpose (a Rust+TS generic IPC envelope with non-empty generated `event_id` and `created_at`, fixture-pinned error taxonomy, and a TS parser that validates rather than erases payload shape)? Are TODOs, stubbed branches, weak assertions, hardcoded metadata, or deferred behaviors hiding incomplete work?

## Shortcuts examined

### WU-0A-06-SHORTCUT-F01 — `event_id` is `format!("event-{nanos}-{counter}")`, not UUID v4

`src-tauri/src/events/ipc_event.rs:75-80` composes the event ID from `SystemTime::now()` nanoseconds plus an `AtomicU64` counter (`NEXT_EVENT_COUNTER`, `ipc_event.rs:10`). Justified by proposal A1 (`proposals/06-wu-0a-06.md:42`): "Event IDs only need to be opaque non-empty strings in Phase 0A. Evidence: the WU contract requires `event_id: string` and acceptance criteria only require non-empty builder output." The contract section "IpcEvent" says only "required non-empty string generated by `build_ipc_event`" (`product-strategy/contracts/wu-0a-06-ipc-event.md:11`); no UUID format is mandated. The atomic counter guarantees uniqueness within a process even when multiple events land in the same nanosecond, and the leading `"event-"` literal guarantees the result is never the empty string by construction. **Not a stub — a real generator that satisfies every documented requirement.**

### WU-0A-06-SHORTCUT-F02 — `created_at` is unix nanos as a string, not RFC3339

`ipc_event.rs:82-91`: `generate_created_at` returns `SystemTime::now().duration_since(UNIX_EPOCH).unwrap_or_default().as_nanos().to_string()`. Justified by proposal A2 (`proposals/06-wu-0a-06.md:43`): "`created_at` only needs to be an opaque non-empty timestamp string in Phase 0A." The contract literally says "required non-empty timestamp string generated by `build_ipc_event`" with no format requirement (`product-strategy/contracts/wu-0a-06-ipc-event.md:15, 34`). The `unwrap_or_default()` collapses to `"0"` if the system clock is before epoch — still non-empty, still satisfies the contract; not a swallowed error. **Justified.**

### WU-0A-06-SHORTCUT-F03 — `IpcEventError` PascalCase via default serde

`src-tauri/src/contracts/ipc_event.rs:17-23` derives `Serialize, Deserialize` with no `rename_all`, so unit variants serialize to their identifier names. The contract pins the wire form as the literal strings `EmptyEventId`, `EmptyWorkspaceId`, `UnknownTopic`, `PayloadSerializationFailed` (`product-strategy/contracts/wu-0a-06-ipc-event.md:60-63`); identical-by-construction with the Rust identifiers. The `ipc-event-errors.json` fixture pins the canonical order (`src-tauri/tests/ipc_event_contract.rs:207-235`). **Justified.**

### WU-0A-06-SHORTCUT-F04 — `Display` for `IpcEventError` reuses serde

`src-tauri/src/contracts/ipc_event.rs:25-32` formats by calling `serde_json::to_string(self)` and trimming the surrounding quotes. Same pattern as `EventTopicError` in WU-0A-05; couples human-readable form to wire form so they cannot drift. The `map_err(|_| std::fmt::Error)` cannot fire in practice because the variants are unit and `serde_json::to_string` of a unit enum does not allocate — but the fallback is a real `fmt::Error`, not `unreachable!()`. **Justified.**

### WU-0A-06-SHORTCUT-F05 — Builder layered through a private `build_ipc_event_with_metadata`

`src-tauri/src/events/ipc_event.rs:44-73` is the validation core; `build_ipc_event` (`:12-29`) and `build_ipc_event_from_raw_topic` (`:31-42`) inject generated metadata. Justified: `EmptyEventId` is documented to fire when the *generated* event ID is empty (`product-strategy/contracts/wu-0a-06-ipc-event.md:67`); a future generator that returns empty must still be caught. The unit test in `events::ipc_event::tests::empty_generated_event_id_is_reported` (`ipc_event.rs:99-111`) exercises that defensive arm via the private helper. **Justified — defense-in-depth, not dead code.**

### WU-0A-06-SHORTCUT-F06 — Payload serialization is checked via `serde_json::to_value(&payload)`

`ipc_event.rs:63`: the builder asserts the payload is JSON-serializable before constructing the event, mapping any error to `IpcEventError::PayloadSerializationFailed`. The `serde_json::Value` is *discarded* (the payload is preserved by-value into the envelope), so this is a pure pre-flight check — no double-encoding, no payload mutation. Test reachability uses a custom `NonSerializablePayload` whose `Serialize` impl returns `Err(serde::ser::Error::custom(...))` (`src-tauri/tests/ipc_event_contract.rs:35-46, 174-190`). **Justified.**

### WU-0A-06-SHORTCUT-F07 — `IpcEventError::EmptyEventId` match-arm panics in the integration test

`src-tauri/tests/ipc_event_contract.rs:191-195` panics with `"{name} should be covered by error taxonomy round-trip, not normal builder input"` when a `build-errors.json` row claims `EmptyEventId`. This is **defensive**: the build-errors fixture documents only the three reachable-through-public-API errors, and `EmptyEventId` is intentionally absent from it; the panic catches a future fixture row that would mis-route the error through public input. The variant itself is asserted via the round-trip in `ipc_event_error_variants_round_trip_and_unknown_variant_is_rejected` (`ipc_event_contract.rs:207-235`) and via the private-helper unit test (F05). **Not a hidden hole.**

### WU-0A-06-SHORTCUT-F08 — TS parser does real shape validation, not blanket `any`

`src/contracts/ipc-event.ts:21-73` validates: object kind, exact key set (sorted, including the optional key only when present), required string types and non-empty `event_id` / `created_at`, `topic` membership in `EVENT_TOPICS`, optional `trace_context_id` typed as string when present. Payload validation is delegated to a caller-supplied `parsePayload(unknown) -> T`, with thrown errors caught and rethrown as `Invalid IpcEvent`. This is the explicit design called out in the proposal: "the TypeScript parser receives a caller-supplied payload parser so payload validation remains explicit at the consuming contract boundary instead of being erased to `unknown`" (`proposals/06-wu-0a-06.md:12`). Coverage by `invalid-events.json` rows: missing field, empty string, unknown topic, extra field, payload rejected by parser (`product-strategy/contracts/fixtures/wu-0a-06/invalid-events.json:1-62`, asserted in `src/test/ipc-event.test.ts:92-99`). **Justified.**

### WU-0A-06-SHORTCUT-F09 — Match on `IpcEventError` in the integration test is exhaustive (no `_` fallthrough)

`src-tauri/tests/ipc_event_contract.rs:148-195` matches `EmptyWorkspaceId`, `UnknownTopic`, `PayloadSerializationFailed`, and `EmptyEventId` explicitly. There is no `_` arm; if a future variant is added, the test fails to compile, which is the desired drift detector. **Justified.**

## Hidden-incomplete-work check

- No `TODO`, `FIXME`, `XXX`, `HACK`, `unimplemented!()`, or `todo!()` markers in any of `src-tauri/src/contracts/ipc_event.rs`, `src-tauri/src/events/ipc_event.rs`, `src-tauri/tests/ipc_event_contract.rs`, `src/contracts/ipc-event.ts`, or `src/test/ipc-event.test.ts`. The `panic!` calls in the test file are diagnostic / drift-detector arms (F07, plus fixture-load failure messages on lines 61 and 63), not stubs.
- No `#[allow(dead_code)]`, no `#[ignore]` tests, no `it.skip(...)` / `it.todo(...)` in the vitest file.
- All four error variants have a reachability path: three through documented fixture inputs, one through the private-helper unit test plus the serde round-trip — and `IPC_EVENT_ERRORS` / `ipc-event-errors.json` parity is asserted in TS (`src/test/ipc-event.test.ts:101-124`).
- The TS file's `// @ts-expect-error` lines on `payload: { kind: 42 }`, `topic: "unknown"`, and `IpcEventError = "OtherError"` (`src/test/ipc-event.test.ts:81-90, 112-113`) are compile-time assertions that the generic and union types reject ill-typed inputs — not silenced lints.
- `#[serde(deny_unknown_fields)]` on the Rust DTO and the exact-key check in the TS parser both reject extra fields, matched by the `extra field` row in `invalid-events.json` and the explicit `extra: true` case in `src-tauri/tests/ipc_event_contract.rs:82-94`.
- `bun run lint`, `bun run typecheck`, `bun run test`, `cargo test`, `cargo fmt --check`, and `cargo clippy --all-targets --all-features -- -D warnings` are all green.

## Verdict

**LOW.** Every choice is either an explicit proposal assumption (A1/A2 for opaque event ID and timestamp), a contract-documented surface (the four error strings, the raw-topic helper), or a deliberate drift detector (the `EmptyEventId` panic arm, the `// @ts-expect-error` assertions, `deny_unknown_fields`). No stubs, no skipped tests, no hardcoded fixture metadata leaking into production paths, no payload-erasing `unknown`. The defensive `EmptyEventId` arm is real validation, not dead code, and the unit test exercises it through the private layered builder.
